# 客观 verify 标准（不依赖 LLM 判断）

> 要求：verify 必须有**客观标准**，不能依赖 LLM 去「觉得没问题」。
> 本文给出 12 条可判定判据、实跑结果，以及**无法客观化的 4 项如何处置**。

---

## 一、判据的设计约束

| 约束 | 含义 |
|------|------|
| **确定性算法** | 只允许：集合差、守恒等式、正则计数、数值比较、哈希一致、图算法、枚举成员、覆盖率比值 |
| **输出结构化** | 必须是 `{total, covered, missing[], verdict}`，**禁止输出「看起来没问题」** |
| **阈值显式** | 阈值可以争议，但必须写出来并可复算 |
| **不得冒充** | 无法客观化者记为 `judgment_required`，**不进自动门禁、不计入 pass** |
| **可复现** | 同输入同输出（两次运行哈希一致） |

## 三、最关键的一条：无法客观化的 4 项怎么处置

我在此前的评估里写过 4 处**依赖我主观判断**的结论。按客观标准，它们**都不能作为「通过」输出**：

| 我此前的说法 | 类型 | 可客观化的替代 | 判定 |
|--------------|------|----------------|------|
| 「还原稿「论证质量优于原稿」」 | 主观（LLM 判断） | warrant 实质非占位率 = 100%；backing 实质非占位率 = 100%；grounds 可追溯率 = 54% | **`judgment_required`** |
| 「依据复核「3 条不合规」」 | 半主观（判定依赖条款语义） | 15 条判定中 15 条含可比较数值/阈值；其余为存在性判定（名称/版本是否废止） | **`partial_objective`** |
| 「评估报告中的「影响度 高/中/低」」 | 主观（LLM 判断） | 改为布尔判据「是否阻断派生量」：当前 15 条规则被阻塞（由依赖图算出） | **`judgment_required`** |
| 「「压缩过程性记述是可接受的取舍」」 | 主观（LLM 判断） | 可客观化的部分：该章数字 token 保留率、该章节点引用覆盖率（均为比值） | **`judgment_required`** |

**为什么这一步很重要**：

- 「论证质量优于原稿」听起来像结论，实际是**我的印象**。可客观化的只有「要件完备性」（warrant/backing 非占位率、grounds 可追溯率）——但**完备 ≠ 更好**，把它写成通过就是拿印象冒充事实；
- 「影响度 高/中/低」完全不可判定。正确做法是换成**二元判据**：「是否阻断派生量」——由依赖图算出，是或否，无争议；
- 「3 条不合规」里，阈值穿越类（>50m ⇒ 一类高层）**可以**完全客观化（数值比较）；但「是否已废止」需要依据原文的发布/废止记录。**当前只有 22 条依据有外部原文，范围缺口必须显式标注**，不能把「已核 22 条中的 3 条不合规」说成「全报告 3 条不合规」；
- 「压缩是可接受的取舍」是**业务判断**，必须由客户/编制单位确认。门禁只能报告保留率（比值，客观），**不得代替「可接受」结论**。

## 四、判据与 LLM 的分工（明确边界）

```
LLM 负责（语义层，允许不确定）       工具负责（判定层，必须确定）
─────────────────────────────    ─────────────────────────────
· 抽取实体/事实/论断/关系              · 判「该抽的都抽了吗」→ 集合差
· 判断证据支持等级                     · 判「值域合法吗」→ 枚举成员
· 组织论证与表述                       · 判「数字对不对」→ 数值重算
· 发现原件矛盾                         · 判「引用闭环吗」→ 集合差
                                       · 判「可复现吗」→ 哈希
        ↓                                        ↑
   产出「候选」                          判定「候选是否合格」
                                        **判定不消费 LLM 的意见**
```

**关键分工原则**：LLM 的产出是**候选**，工具判定候选是否合格。当某个判断无法客观化时，**不能降低标准让它通过，也不能让 LLM 自判**——只能把它移出自动门禁，标为 `judgment_required` 交给人。

## 五、一句话

| 问题 | 答案 |
|------|------|
| verify 有客观标准吗？ | **有，12 条判据全部是确定性算法**，实跑 8/12 通过 |
| 还需要 LLM 参与 verify 吗？ | **不需要**。LLM 只产出候选；判定由工具做，且**判定不消费 LLM 的意见** |
| 遇到判不了的怎么办？ | 记 `judgment_required`，**既不放行也不自判**，交人工 |
| 我之前有哪些结论不合格？ | **4 处**（质量优于原稿、影响度分级、不合规范围、取舍可接受性）——已改为客观代理或标记待人工 |
