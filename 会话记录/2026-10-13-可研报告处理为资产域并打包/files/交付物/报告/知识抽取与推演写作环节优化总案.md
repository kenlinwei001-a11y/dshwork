# 知识抽取与推演写作：环节优化总案

> 本文覆盖**抽取侧 7 个环节 + 装配侧 5 个环节**，每一环节给出：优化前的缺陷、优化后的判据、客观算法、实测结果。所有数字均取自门禁输出文件，可复算。

## 一、三类根因（全部来自实测，不是推测）

| 根因 | 证据 | 影响面 |
|------|------|--------|
| **① verify 遍历产物** | `validate_extraction` 三个循环均为 `for x in ext.get(...)` | 对产物集合 P 的遍历，**逻辑上不可能**发现「属于源 S 而不属于 P」的元素 |
| **② 关系词表缺项** | `TEN_RELATIONS` 中无 `cites`/`restates`/`causes`/`derives` 等 | 缺 6 类，直接表现为 `premise_refs`/`derived_from` 字段空置 |
| **③ 源侧缺层/缺索引** | 总论章 0 条论断；435 条关系的起点是主体名而非节点 ID | 复述层不存在→改一处漏三处；图不可连通→无法做影响传播查询 |

**关键认识**：这三条都是**机制允许遗漏**，不是「不够仔细」。同一双眼睛看两遍，看不见自己的盲区。

## 七、环节优化的四条原则（可迁移到其它项目）

1. **先有「源」，才有「完整」**：不建源侧索引，就无法提出「漏了什么」这个问题；
2. **门禁放在可重做单元的出口**：一个 partition、一个 chunk、一节、一个域，早一步拦住 = 重做该单元；晚一步 = 重做全部 + 归因已丢；
3. **判据必须客观**：只用集合差/守恒/正则/数值比较/哈希/图算法/枚举/覆盖率；判不了的记 `judgment_required`，**既不放行也不自判**；
4. **判定不消费 LLM 的意见**：LLM 产出候选，工具判定候选是否合格；「我觉得没问题」永远不进 pass。
