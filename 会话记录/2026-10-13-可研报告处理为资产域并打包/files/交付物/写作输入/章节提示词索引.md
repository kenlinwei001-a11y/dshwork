# 章节提示词索引

> 用法：每章起草前读本文件对应行 + 该章的行内注入；`prepare` 没做完不要动笔。
> 结构：**十个章节族各写一次**（不按章重复），16 个一级章各自指向所属族并附本项目注入。

---

## 一、通用约束

**硬规则**
- 正文不许出现字面数字，只能写 {{节点ID}}
- 不许新增图上没有的事实。要新增，先入图
- 每条论断的 Toulmin 必填项要齐（论点/论据/保证/支撑）；保证原文没给出就标注「未给出」，不代拟
- 通用条款只在该专业显式允许时才许写，且须标注
- 冲突一律「待审」并列，不裁决；缺值显式留白，不估算

**文风**
- 结论前置：先说是什么，再说为什么
- 一段一个意思。三行以上的段落多半塞了两件事
- 不用「较为」「基本上」「原则上」这类没有信息量的限定词
- 表格能说清的不写成段落；但表格前要有一句话说明这张表要看什么

**自检**：写完逐句问——被评审追问「依据是什么」，这句我答得上吗？答不上的就是刚编的

## 二、章节族提示（十族各一次）

### annex　附件

- **法定覆盖**：附表、附图、批复与会议纪要
- **核心问题**：把支撑性文件逐件列清，并标注缺件
- **形态**：极短。清单式　｜　**评审盯什么**：缺件是评审退回补正的常见原因，主动标注反而加分
- **起草前置（prepare）**：
  - 附件清单须与实际取得的文件一致
- **必须写到（must_state）**：
  - 附件逐件列出（名称 + 文号 + 状态）
  - **待补充件显式标注**
- **本章特有的坑（must_not）**：
  - 把未取得的附件列为已具备

### background　项目建设背景和必要性

- **法定覆盖**：项目建设背景、规划政策符合性、项目建设必要性
- **核心问题**：为什么**非本单位、非现在、非这个规模**不可
- **形态**：论证为主。是全篇论证密度最高的一章　｜　**评审盯什么**：这一章最容易被问「你们论证的是这个项目还是这类项目」
- **起草前置（prepare）**：
  - 现状不足必须问到客户，**不许凭「一般都这样」写**
  - 需求缺口要先算出来，这一章引用结论
  - 上位政策做适配性评估并交客户勾选，未采纳的留痕
- **必须写到（must_state）**：
  - 现状的具体困难（拥挤程度、危房、设备老化），要有数
  - 缺口的量化结论，并指向规模章
  - 政策与规划的对照，逐条到条款
- **本章特有的坑（must_not）**：
  - **断链**：从「国家重视某某领域」直接跳到「本校必须建这栋楼」。中间那步（现状多少、指标多少、差多少、差导致了什么）不能省
  - 背景写成行业综述。凡不能连到「所以本项目要建」的段落都该删
  - 引一份只有原则性表述的规划说「符合规划要求」

### bidding　招投标方案（建设管理）

- **法定覆盖**：建设管理方案
- **核心问题**：哪些必须招、怎么招、依据哪条门槛
- **形态**：短。以表为主　｜　**评审盯什么**：门槛比对是可机检的；金额口径不一致会被追到底
- **起草前置（prepare）**：
  - 逐项金额与门槛值比对，**判定的依据条款要到条**
  - 招标组织形式与方式须与资金性质匹配
- **必须写到（must_state）**：
  - 招标范围（逐项：勘察/设计/施工/监理/设备材料）
  - 招标组织形式与方式，以及每一步的适用依据条款
- **本章特有的坑（must_not）**：
  - 只写「依法招标」不写门槛判定过程
  - 表内的招标估算金额与投资估算表不一致却不说明

### conclusion　结论与建议

- **法定覆盖**：主要结论和建议
- **核心问题**：逐维度给结论，并把未闭合事项交代清楚
- **形态**：短　｜　**评审盯什么**：结论与前文不一致是低级但致命的问题
- **起草前置（prepare）**：
  - 全部维度的论证已完成，不适用的已显式声明
- **必须写到（must_state）**：
  - 逐维度的结论，不是笼统一句「可行」
  - 尚待落实的事项与建议
- **本章特有的坑（must_not）**：
  - **出现一个新数**。这一章一个新事实都不许有
  - 把声明不适用的维度略过不写。声明了也要写在结论里

### energy_env　节能环保与双碳

- **法定覆盖**：节能分析、环境影响分析、碳达峰碳中和分析
- **核心问题**：能耗多少、达不达标、污染物怎么处置、碳排怎么算
- **形态**：中等　｜　**评审盯什么**：能评与环评是独立程序，可研里写的口径要与之一致
- **起草前置（prepare）**：
  - 能耗指标先查基准值（须标参照值）
  - 用能量由面积与指标算出，不手填
- **必须写到（must_state）**：
  - 用能种类与用量、对标的标准限值、节能措施、污染物与处置、碳排测算
- **本章特有的坑（must_not）**：
  - 节能措施写成清单堆砌。要说明**这些措施使指标达到了什么水平**
  - 碳排只写「符合双碳要求」。要有测算

### investment　投资估算与资金筹措

- **法定覆盖**：投资估算、资金筹措方案、财务可持续性分析
- **核心问题**：钱怎么算出来的、从哪来、够不够
- **形态**：表为主。正文说明口径与依据　｜　**评审盯什么**：费率取值与不含项是两个必查点
- **起草前置（prepare）**：
  - 费用构成分项、价格年份、费率依据齐备
  - **不含项清单必须明确**：家具、专用设备、大市政增容费
  - 造价链与资金链在图上跑通，硬等式成立
- **必须写到（must_state）**：
  - 费用构成分项与合计，各项依据
  - 资金来源与落实情况，自筹部分要有落实证明
  - 分年度资金安排
- **本章特有的坑（must_not）**：
  - 分项之和对不上合计。这是可机检的，不该带进出稿
  - 自筹部分只写「学校自行筹措解决」。要写清楚从哪笔钱出
  - 拿同类项目单方造价充当本项目取值。它只能佐证合理性

### operation　项目运营方案与绩效

- **法定覆盖**：运营方案、绩效管理方案
- **核心问题**：建成后谁来管、怎么管、拿什么衡量管得好不好
- **形态**：中等偏短　｜　**评审盯什么**：政府投资项目的绩效目标会进入后评价，写虚了后面兑现不了
- **起草前置（prepare）**：
  - 运营主体与管理机构属客户决策，必须问到
- **必须写到（must_state）**：
  - 运营模式、管理机构与人员、运行经费来源
  - 绩效指标：产出指标 + 效益指标 + 满意度指标，要可量化
- **本章特有的坑（must_not）**：
  - 只写运营模式不写绩效。**这是 2023 大纲新增而旧口径报告普遍缺的一项**
  - 绩效指标写成「提高使用效率」。要写成可测的数

### overview　概述 / 总论（含项目单位概况）

- **法定覆盖**：项目概况、项目单位概况、编制依据、主要结论和建议
- **核心问题**：让评审在两页内知道——建什么、多大、多少钱、钱从哪来、结论是什么
- **形态**：短。以表为主，正文只做串联　｜　**评审盯什么**：评审先读这一章再决定读得多细。数字对不上，后面每章都会被怀疑
- **起草前置（prepare）**：
  - 全篇关键节点已冻结。**这一章最后写**，它是全篇的投影
  - 单位概况的事实性描述须交客户核对
- **必须写到（must_state）**：
  - 建设内容与规模、总投资与资金来源、建设周期、结论
  - 编制依据清单（法规、规范、批复、委托），逐条带文号或编号
- **本章特有的坑（must_not）**：
  - 出现全篇别处没有的数。这一章只复述，不产出
  - 把结论写成「项目可行」四个字；要写清在什么条件下可行

### scale　需求分析与建设规模

- **法定覆盖**：需求分析、建设内容和规模、项目产出方案
- **核心问题**：这个规模是怎么算出来的，每一步都要能被逐条复核
- **形态**：篇幅重心。表与算式为主，每张表前有一句话说明看什么　｜　**评审盯什么**：评审会拿计算器逐条验。一步对不上，整章的可信度就没了
- **起草前置（prepare）**：
  - 分类人数、现有存量、面积指标三者齐备，且**口径已显式声明**
  - 测算链在图上跑通，偏差率算出
- **必须写到（must_state）**：
  - 测算过程分步列出：分类 → 指标 → 分项需求 → 合计
  - 设计规模与需求测算值的比对，偏差超阈值要说明超出部分的构成
- **本章特有的坑（must_not）**：
  - 只给结论不给过程。这一章的价值就在过程可核
  - 口径混用（全校/本校区/本期）。**这是本类项目最高频的错误，人眼极难发现**

### schedule_risk　实施进度与风险管控

- **法定覆盖**：实施进度安排、风险管控方案、应急预案
- **核心问题**：什么时候干完、有什么风险、怎么应对
- **形态**：短。以横道图与风险表为主　｜　**评审盯什么**：前置条件未闭合不影响可研成立，漏掉才是问题
- **起草前置（prepare）**：
  - 里程碑由客户给，**不许自行拆工期**——拆出来的节点会被当成承诺
  - 前置条件未闭合的事项（手续、专项评估、增容）逐条列出
- **必须写到（must_state）**：
  - 进度安排与关键节点
  - 风险清单：识别 + 等级 + 应对措施，前置条件未闭合的必须在列
- **本章特有的坑（must_not）**：
  - 风险写成通用清单（「政策风险」「市场风险」）。要写本项目实际存在的
  - agent 自行判定风险等级。候选交客户确认

### site　项目选址与要素保障

- **法定覆盖**：项目选址或选线、项目建设条件、要素保障分析
- **核心问题**：地能不能用、水电气热通不通、要素有没有落实
- **形态**：中等。以条件清单为主　｜　**评审盯什么**：要素未落实不影响可研成立，但**必须如实交代并进风险章**
- **起草前置（prepare）**：
  - 用地权属与规划条件到位
  - 地域参数按项目所在地查（抗震烈度、气象、地质），**不是按单位注册地**
  - 市政接入条件：公开规划可查，本项目的接入意见须向客户要
- **必须写到（must_state）**：
  - 用地权属状态、规划控制指标、与总体规划的关系
  - 各类要素的供给条件与落实情况，未落实的写明办理计划
- **本章特有的坑（must_not）**：
  - 把区域供给能力当成本项目的接入条件已落实。两者要分开写
  - 用单位注册地的地域参数。多校区单位这里最容易错

### technical　技术方案（建设内容与工程方案）

- **法定覆盖**：技术方案、设备方案、工程方案
- **核心问题**：采用什么方案、依据什么、关键取值是多少 —— 三句都要答得上
- **形态**：篇幅重心之一。按专业分节，每节结论前置　｜　**评审盯什么**：评审看得最细的一章。追问的是数字，不是「有没有」
- **起草前置（prepare）**：
  - **先做规范判定**：建筑分类与耐火等级、抗震设防类别、防火分区上限、用水定额、用电指标。判定结论必须带条款依据
  - **再做参数推导**：计算负荷、变压器容量、冷热负荷、最高日用水量、消防水池容积
  - **方案比选项交客户定**：结构形式、空调形式与冷热源、装配率与绿建目标。给候选 + 比选要点
  - **设计单位专属的项必须先要到**：柱网、平面布置、管线综合、工艺专项条件。要不到就留白
- **必须写到（must_state）**：
  - 各专业：采用什么方案、依据哪条规范、关键取值多少
  - 本项目特有的技术条件要写实（实验室通风、机房散热、防振）
- **本章特有的坑（must_not）**：
  - 写「设置机械通风系统」「按二级负荷设计」「按现行规范设置」这类句子。每一句都对，每一句都没说本项目
  - 在有特殊性的专业上写通用条款
  - 编设计单位专属的取值。这是最难被发现的一种编造
