# 语义抽取契约（LLM 层）· 工序 4 本体抽取

你正在处理一份**高校科研用房类可行性研究报告**（上海财经大学中山北一路校区大数据研究中心，2019 年修订版，编制单位上海同济工程咨询有限公司）。

你的任务是：把分配的 chunk 分区，按**下方固定 schema** 抽取结构化知识，输出一个 JSON 数组。
抽取结果会经 `validator.py` 确定性校验（字段缺失/枚举非法会被丢弃），并被编译进语义图谱。

## 输出位置与格式

只写一个文件：`build/extractions/<你的分区号>.json`（例如 `build/extractions/P2.json`）。

文件内容是 **JSON 数组**，每个元素对应一个「抽取单元」（通常是一个 chunk）：

```json
[
  {
    "chunk_id": "c-xxxxxxxxxxxx",
    "facts": [
      {"subject": "本项目", "predicate": "总建筑面积", "value": "18319", "unit": "㎡",
       "time": "2019", "kind": "quantity", "source": "c-xxxxxxxxxxxx",
       "from": {"locator": "1.3 技术经济指标 表1-2", "verbatim": "总建筑面积 18319 ㎡"}}
    ],
    "rules": [
      {"id": "R-建筑面积合计", "kind": "compute", "label": "总建筑面积",
       "expr": "round({地上建筑面积}+{地下建筑面积}, 0)", "deps": ["地上建筑面积", "地下建筑面积"],
       "target": "总建筑面积", "guard": "missing_any_dep => undefined",
       "basis": "建标191-2018", "serves": ["D3 建设规模"]}
    ],
    "claims": [
      {"id": "CL-必要性-01", "text": "……", "claim_type": "conclusion", "type": "judgment",
       "status": "unverified", "evidence_refs": ["EV-必要性-01"], "premise_refs": [],
       "derived_from": [],
       "toulmin": {"claim": "……", "grounds": "……", "warrant": "……", "backing": "……",
                   "qualifier": "……", "rebuttal": "——"}}
    ],
    "evidence": [
      {"id": "EV-必要性-01", "kind": "E1", "doc": "《上海财经大学\"十三五\"发展规划纲要》",
       "chunk": "c-xxxxxxxxxxxx", "quote": "……", "status": "verified",
       "locator": "3.1.1"}
    ],
    "relations": [
      {"from": "EV-必要性-01", "to": "CL-必要性-01", "type": "supports"},
      {"from": "大数据研究中心", "to": "上海财经大学", "type": "part_of"}
    ]
  }
]
```

## 铁律（违反即视为无效抽取）

1. **不许编造**。只抽文档里真实出现的内容。抽不到就留空数组 `[]`。绝不估算、不套用同类项目经验值、不补写"暂按经验值"。
2. **数值必须带单位**，且 `verbatim` 必须是原文可检索的字符串。
3. **同一指标在不同章节出现时，`subject` 与 `predicate` 必须完全一致**——这是跨章数字一致性检查（工序 5 推演回放）的唯一依据。例如各章都写"总建筑面积"时，统一为 `subject="本项目", predicate="总建筑面积"`，不要写成"总建筑面积"、"项目总建筑面积"、"总建筑规模"。
4. **冲突不裁决**：若你发现同一 (subject,predicate) 在两处数值不同，两处**都抽出来**（各是一条 fact），不要挑一个。系统会把它们标为「待审」。
5. **Claim 必须绑定 evidence_refs**。找不到证据的 Claim 也要抽，但 `evidence_refs` 留空数组，系统会登记为缺口（不硬撑结论）。
6. **Toulmin 六元组**：`warrant`（保证/推理许可）最容易被省略——它是评审最爱抓的断链点。原文没写的就是 `""`，**不要替它编一个保证**。
7. `kind` 取值：定量指标用 `"quantity"`；判断题/文本型用 `"judgment"`；纯文本描述用 `"text"`。

## 受控词表

**facts.predicate**（尽量选用，不够用可扩展，但要保持全篇一致）：
`项目名称` `建设单位` `建设地点` `建设性质` `用地面积` `总建筑面积` `地上建筑面积` `地下建筑面积`
`拆除面积` `容积率` `绿地率` `建筑高度` `层数` `结构形式` `设计使用年限` `抗震设防烈度` `耐火等级`
`总投资` `建安工程费用` `工程建设其他费用` `预备费` `拆除费用` `资金来源` `国拨资金` `学校自筹`
`工程费用` `设备购置费` `安装工程费` `单位造价` `建设工期` `开工时间` `竣工时间`
`科研人员数` `研究生数` `人均建筑面积指标` `研究中心的个数` `实验室间数` `班次`
`年耗电量` `年用水量` `变压器容量` `计算负荷` `冷负荷` `热负荷` `换气次数` `绿地面积` `停车位`

**facts.subject**：项目级指标统一用 `"本项目"`；单体用建筑名；专业系统用系统名（如 `"变配电系统"`、`"空调系统"`、`"给水系统"`）；机构用机构名。

**rules.kind**：`compute`（可计算）或 `select`（判定/选取）。
`rules.expr` 用 `{变量名}` 占位，占位名必须与本分区抽出的 `facts.predicate` 或 `target` 一致。

**claims.claim_type** ∈ `fact` / `hypothesis` / `inference` / `conclusion` / `recommendation`
**claims.type**（论断性质）∈ `judgment` / `prediction` / `causal` / `suggestion` / `risk`

**evidence.kind**（证据分级，六选一）：
- `E1` 客户/单位内部资料（校内规划、党委会纪要、业主提供资料）
- `E2` 规范/标准/定额（建标 191-2018、各类 GB/JGJ/DGJ 等）
- `E3` 政策法规与上位规划（国家战略、地方规划、批复文件）
- `E4` 公开统计数据（年鉴、统计公报）
- `E5` 第三方委托成果（设计方案、造价书、地勘报告、环评）
- `E6` 专家判断 / 类推 / 无外部依据

**relations.type**（十类，只能用这十类）：
`has_value` `has_attribute` `instance_of` `part_of` `causes` `depends_on` `supports` `contradicts` `temporal` `located_in`

## 高校科研用房领域的特别关注（评审看得最细的地方）

- **规模论证链**：分类人数 × 人均建筑面积指标 ⇒ 应建规模。人数必须**分类**（科研人员 / 研究生 的人均指标不同）。注意原文引用的规范名称与编号是否正确（如"《普通高等学校建筑规划面积指标》（建标191-2018）"）。
- **投资构成闭合**：建安工程费 + 工程建设其他费用 + 预备费 + 拆除费用 = 总投资。分项与合计要能对上；对不上就是冲突，两处都抽。
- **拆除重建的四件事**：原建筑拆除面积、拆除费用、拆除产生的资产处置、新建与原功能的关系。
- **实验室专项**：通风柜台数、换气次数、排风量、实验废水处理、防振、洁净等级。
- **仪器设备费是否计入总投资**——各校口径不同、金额巨大，原文怎么写的要如实抽。
- **论证断链**：从"国家有大数据战略"到"本校必须建这栋楼"，中间那步保证（warrant）原文是否写出来。没写就如实留空。

## 数量建议（不要为了凑数灌水，也不要漏掉关键指标）

- facts：本分区内真实出现的定量指标全部抽出（通常 10–60 条）
- rules：原文明确给出的计算公式/判定规则（通常 0–8 条；很多章没有规则，`[]` 是正确答案）
- claims：**论证单元**级（必要性论证、规模论证、方案比选结论、投资结论、风险判断），通常 2–15 条
- evidence：每条 claim 至少 1 条证据引用（找得到时）
- relations：事实间依赖、证据→论断、部分→整体，通常 10–60 条

完成后回复一行：`<分区号> extracted: facts=N rules=N claims=N evidence=N relations=N`。
