## 依赖关系（16 域依赖图）

```
ontology（根）
 ├─ entity_relation / variable / argument_chain / report_structure / function(经 variable)
 ├─ rule ← variable ; invariant ← variable ; scenario ← variable, rule ; cost_risk ← variable, function, rule
 ├─ skill ← ontology, rule, function ; task_dag ← ontology, rule, skill, function

 └─ quality_gate ← ontology, rule, argument_chain ; reuse_strategy ← ontology, quality_gate
```

影响传播示例（沿依赖图正向传播）：

- 变更 `ontology`（新增 Claim 实体类型或属性）→ 受影响 **16** 个下游域
- 变更 `variable`（新增/变更一个输入变量（如分类人数口径））→ 受影响 **11** 个下游域
- 变更 `rule`（新增或调整一条计算规则）→ 受影响 **8** 个下游域

## 扩展资产（16 域契约之外的本次新增）

kp 内置的 16 域契约（`corpus_pipeline.full_emit.DOMAIN_SPECS`）未包含下面两项，本包以独立资产文件承载：

| 资产 | 文件 | 为什么要沉淀 | 挂载到哪些域 |
|------|------|--------------|--------------|
| **规范依赖**（依据→技术函数的约束与保证） | [`reuse/regulatory_dependency.yaml`](../SHUFE-BDC-2019-001/reuse/regulatory_dependency.yaml) | 这类依赖是**领域知识**而非项目事实：施工≥400万必须招标、一类高层耐火等级不得低于一级、使用面积系数＝使用面积/建筑面积——这些关系在任何同类项目上都成立… | `ontology`、`rule`、`invariant`、`reuse_strategy`、`quality_gate`、`prompt` |
| **逐章提示词**（每章是不同的活） | [`style/section_prompts.yaml`](../SHUFE-BDC-2019-001/style/section_prompts.yaml) | 用一套通用提示词写十几章，出来必然是同一种腔调的流水账；必要性章在论证、规模章在测算、技术章在判定与取值、投资章在归集、结论章在复述 | `prompt`（骨架）/ `style/section_prompts.yaml`（本项目实例化，16 章） |

> 逐章提示词覆盖 16 个一级章，用到 11 个章节族；每章都带 `prepare`（起草前置）/ `must_state` / `must_not` / `review` / `shape`，并注入本项目的可用节点、待审冲突、缺口与依据绑定。

kp 内置的 16 域契约（corpus_pipeline.full_emit.DOMAIN_SPECS）未包含本资产。本包以独立资产文件 reuse/regulatory_dependency.yaml 承载，并挂到 ontology/rule/invariant/reuse_strategy/quality_gate 五域的 reusable_form 上；若下游要将其升为「第 17 个资产域」，需在 kp 的 ASSET_DEPENDENCIES 中注册：regulatory_dependency: [ontology, rule]（本包不改动上游工程）。

## 借形不借值边界

每个域文件都带 `reuse_boundary`，明确 **可继承**（结构/规则/口径/术语/句式/关系类型）与 **禁止继承**（数值/单位取值/实体名/政策文号/规范版本/结论）。域文件正文中不含可直接写进新报告的项目专属数值。
