# dsh-task-dag —— 项目任务图谱插件

你手上同时推进的项目可能不只一个：一个科研项目、一个工程项目、一个商业项目可能同时在推进，每个项目里又横着大量性质不同的任务。用 Harness 工作时，我们习惯用 Project / Workspace 把它们分开，再为每个具体任务开一个对话。Harness提高了我们的工作效率，但项目一多，进度就散落在几十个会话里：哪一步已经做完、下一步该做什么、哪个任务被什么卡住，往往只能靠回忆和翻聊天记录。

`dsh-task-dag` 把这些信息从会话历史里提出来，变成一张可视化、可编辑、Agent 也能读写的任务图：节点是任务，节点上的前置条件表达依赖，状态由事实推导。人因此可以从「一个个任务的执行者」，回到「监督项目有序推进的管理者」。

---

## 1. 设计理念

### 1.1 项目/任务/Workspace/Project

一个人同时置身于多个现实项目是常态：科研、工程、商业，甚至同一个项目里的不同方向。这些`项目`不是 Harness 里的 Project / Workspace——后者是工具层面的容器，用来组织文件和会话；前者是现实世界里需要推进、有目标、有依赖、有里程碑的事情。

### 1.2 机器转得越快，工人越累

Agent 把「执行一项任务」的成本压得很低，任务数量随之膨胀。当多个项目同时推进时，人要记住的事情变成：每个项目做到哪一步、哪些任务在等前置条件、哪些会话正在跑、哪个会话的上下文快满了、哪个任务该交给谁。

这很像工厂：机器转得越快，工人越需要盯着更多产线。效率提升没有自动变成掌控感，反而把协调负担集中到了人身上。

### 1.3 从执行者到管理者

把视角抬高一层：人的角色不是逐条执行任务，而是监督项目有序推进。管理者需要的信息其实很朴素：

- 这个项目现在完成到什么程度？
- 哪些任务马上可以做，哪些被什么卡住？
- 每个任务由哪个会话在做，上下文还够不够？
- 哪些重复性任务可以定时自动推进？
- 某个任务失败时，会不会让后续永远等不到？

`dsh-task-dag` 就为这几类问题而做：把项目流程可视化，让人随时看得到全局，并能在图上直接推进项目。

### 1.4 概念映射

| 现实世界 | 在 Harness / Agent 里对应什么 | 插件怎么建模 |
|---|---|---|
| 一个现实项目 | 通常用一个 Workspace 承载 | 一张 Graph，存在该 Workspace 的项目目录里，随项目文件走 |
| 一项任务 | 一段又一段对话、Session | 一个 Node，是进度与状态的唯一载体 |
| 任务之间的依赖 | 只存在于人脑和聊天记录里 | 节点上的前置条件（Condition），边表示「某个节点满足了某个条件」 |
| 任务正在被推进 | Session 里跑着的 Agent | 节点上的有序会话链，每个节点同一时刻只有一个当前会话 |
| 执行者 | Agent，可指定预设、模型、推理强度 | 节点的执行设置；交接与定时执行新建会话时带上 |
| 项目全貌 | 侧栏里越堆越长的会话列表 | SVG 三栏画布：项目列表、任务图、节点详情 |
| 项目里程碑 | 只能靠人记 | 图上的里程碑节点标记 |

### 1.5 由此确定的几条约定

1. **项目 = Workspace（存放单位）**：现实项目通常用一个 Workspace 承载，一个 Workspace 只有一张图，图存在项目目录里，可以随 git 共享。这是存放约定，不是概念等同；项目横跨多个 Workspace 时，当前只能选一个 Workspace 放图。
2. **节点 = 任务**，是进度与状态的唯一载体；会话只是任务的工作现场。
3. **状态只存节点自己的事实**。「能不能开始」永远由前置条件的满足情况算出来，不落盘——否则一定会有两处真相打架。
4. **会话链是顺序的，不是集合**。新会话接手旧会话时，旧会话退休但保留记录，仍然可以打开、切回。
5. **交接不是 fork**。交接 = 新建空会话 + 一份短的确定性简报，目的是压缩上下文，而不是复制上下文。
6. **可视化是入口，不是附属视图**。管理者的第一动作应该是看图和改图，而不是翻会话。

## 2. 功能

### 2.1 五态节点

| 状态 | 中文 | 语义 | 参与可开始计算 |
|---|---|---|---|
| `planned` | 待规划 | 还没拆解/没准备好，先在图上占位 | 否 |
| `todo` | 待开始 | 已就绪；条件全部满足即可开始，否则被阻塞 | 是 |
| `doing` | 进行中 | 正在执行 | 否 |
| `done` | 已完成 | 只有已完成能实现前置条件 | 否 |
| `failed` | 已失败 | 失败终态；不能作为任何节点的前置 | 否 |

节点卡片左侧色条与状态点沿用主题令牌，五种状态的颜色与 DSH 的「任务看板」插件一致：

| 状态 | 颜色令牌 |
|---|---|
| 待规划 | `--dsw-alias-label-tertiary` |
| 待开始 | `--dsw-alias-state-business-primary` |
| 进行中 | `--dsw-alias-state-warn-primary` |
| 已完成 | `--dsw-alias-state-success-primary` |
| 已失败 | `--dsw-alias-state-error-primary` |

已失败节点的约束：

- 不能作为其他节点的前置，连边会被拒绝。
- 把节点改成「已失败」时，如果它还有后继，默认拒绝；必须显式选择「失败并解除依赖」，它会同时解除全部出边，不会留下永远等不到的后继。

### 2.2 前置条件与「可开始」的计算

每个节点持有自己的前置条件列表，例如「需求评审通过」「训练数据就绪」「外部审批」。

- 条件可以单独添加，也可以改名、删除；条件与节点是两回事。
- 连边表示「A 满足了 B 的某个前置条件」，边记录的是目标节点上的 `conditionId`，不是裸的 A→B。连边时必须选择 A 满足哪个条件，也可以现场新建。
- 同一条条件可以被多个节点满足：任一节点已完成即满足（OR）。
- 一个节点可以有多个条件：全部条件都满足才能开始（AND）。
- 没有任何条件的节点可以直接开始；声明了条件却没人满足的节点会被有意阻塞。
- 环检测在服务端强制执行，图上不会出现成环依赖。

对外的派生结果（永远不落盘）：

- `ready(n)`：状态为待开始，且所有条件满足。
- `blocked(n)`：状态为待开始，且至少一个条件未满足。
- `progress`：完成数、总数、可开始、阻塞、进行中、失败、待规划。只反映计数，不含「项目是否结束」标志。

**里程碑**：一张图最多有一个里程碑节点。里程碑只是给一个节点打的标记，可以是任意状态，也可以作为其他节点的前置；里程碑节点完成只表示它自己完成，不代表项目结束，其他节点仍按各自的状态与前置条件独立推进。

### 2.3 会话链与交接

节点上的会话按顺序排成一条链，每个节点同一时刻只有一个「当前会话」。

- 当前会话高亮；已交接的会话灰显，仍然可以打开、可以切回。
- **退休不等于删除**，也不等于归档：退休只表示插件不再把它当作该节点的当前工作现场。
- 节点详情显示上下文水位（`projectedTokens / contextWindow`），超过 60% 时提示「建议交接」。
- 一个会话只属于一个节点；同一节点要换执行现场，走交接。

交接有两种入口：

| 按钮 | 行为 |
|---|---|
| **交接新会话** | 新建空会话 → 生成简报 → 把简报作为首条消息发出并立即开跑 → 旧会话退休 |
| **交接新会话（空会话）** | 只新建空会话并挂上，不发任何内容，由你开第一句 |

简报是确定性抽取（不调模型），包含：任务标题/状态/任务描述、已完成与未完成的前置条件、完成后会解锁的后续、旧会话最后一条助手回复（截断）、最近 3 条用户请求（各自截断），结尾要求新会话先复述理解再继续。新会话通常只带 1–2k token，而不是几万 token 的历史。

### 2.4 每个节点的执行设置

每个节点可以单独绑定：

- `agentPreset`：Agent 预设 id；留空跟随宿主默认。
- `model`：模型 id（`provider/model` 或裸模型 id）；留空跟随宿主默认。
- `reasoningEffort`：推理强度 id（由所选模型公布）；留空使用该模型的默认强度。

模型与推理强度使用与 DSH 对话输入框一致的 combobox：先选模型，模型公布推理强度时再选一档。模型目录优先直接读宿主的 LLM registry，读不到时退回 `session/modelCatalog`。

节点上挂接的**当前会话**会立即应用这组配置；「交接新会话」和「定时执行」新建会话时也会带上它。应用失败只记警告，不会阻断图操作，会话继续使用原配置；警告显示在界面底部的状态提示里。

### 2.5 定时执行

每个节点可以配置一条 5 段 cron（`分 时 日 月 周`，本地时区），例如 `0 9 * * 1-5`。

Host 侧每 30 秒扫描一次，到期后：

1. 先按「从当前时间往后算」推进下一次执行时间，不补跑停机期间错过的执行。
2. 不满足以下任一条件就跳过，并记录原因：节点状态是待开始、所有前置条件已满足、没有正在运行的当前会话、宿主会话网关可用。
3. 通过后按顺序：提交「进行中」→ 用节点的预设/模型建新会话 → 挂到节点会话链（`handoff.mode = 'scheduled'`）→ 改名 → 发送确定性执行简报。
4. 每 5 秒检查一次执行会话：轮次正常结束则节点改「已完成」，`turn/end` 报错则改「已失败」并解除出边。人在这期间改了节点状态或换了当前会话，就尊重人的修改，不覆盖。

调度状态（下次执行时间、上次触发/结果/错误）随节点保存在 `graph.json` 里，跟项目一起走；重启后节点仍处于进行中时，会重新接上对 `lastSessionId` 的结算跟踪。

### 2.6 画布与界面

侧栏多出一个「任务图谱」入口，点开是整宽的三栏界面：

```
┌──────────────────────────────────────────────────────────────────────┐
│ 项目 ▾  3/8 完成 · 2 个可开始                                        │
├──────────┬───────────────────────────────────────┬───────────────────┤
│ 项目列表 │            SVG 画布                    │   节点详情        │
│ 项目A ●  │   节点 = 任务卡片，箭头 = 满足的条件    │  状态 / 条件      │
│ 3/8      │   分层避交叉；拖动节点推开重叠          │  执行设置 / 定时   │
│ 项目B ●  │   双击空白新建；拖右缘手柄连边           │  会话链 / 任务描述 │
└──────────┴───────────────────────────────────────┴───────────────────┘
```

- **布局**：左右两栏之间的分隔条可以拖动，宽度会记住；选中分隔条后可用左右方向键微调、双击恢复默认宽度。
- **字体**：插件的字号和字体跟随 DSH「设置 → 通用 → 字体大小」的全局值（`--dsh-content-font-size`），不会出现局部字号偏小。
- **左侧是跨项目总览**：每个项目一行，显示进度和当前可做数，点一下切图。
- **画布**：滚轮缩放、拖背景平移、拖节点记位置、双击空白建节点、从节点右缘拖到另一个节点连边；连边后选择它满足目标节点的哪个前置条件。边会主动绕开它不连接的节点：普通曲线若会穿过无关节点，就改走带圆角的正交绕行路径，平行边之间保持分道。
- **自动布局**按拓扑深度分层，层内用重心排序和相邻交换尽量消除可避免的边交叉；互不相连的子图各自布局后竖向排开；孤立节点集中打包成网格。
- **布局模式**按钮位于「新建节点」和「自动布局」之间，点击切换「自由 / 网格」。网格使用 320×198（宽高比约 1.616，接近黄金比例）的矩形网格，节点中心吸附到网格中心并占互不重复的格子；切换时会把所有节点吸附到空格子并记住模式，网格模式下显示淡色网格线。
- **拖动节点**：自由布局下，落点会实时把其他重叠节点沿最小位移方向推开，并级联处理被推开的节点；网格布局下，卡片在拖动过程中连续跟随指针，松手后才吸附到最近的空格子。松手后保持新落点直到 Host 快照确认，不会先闪回旧位置。
- **节点详情**（从上到下）：
  - 标题 → 任务描述 → 状态。任务描述支持 Markdown 的「编辑 / 预览」，工具栏提供加粗、斜体、行内代码、列表、引用和标题；描述框下方的拖动条可以调整高度并记住。
  - 标题、任务描述、cron 与条件重命名都会在停顿后自动保存（后台静默提交，不会禁用输入框或抢走焦点），并在失焦、切换节点/项目或关闭详情面板前先冲刷草稿，不会因点选别的节点而丢失。
  - 前置条件：添加、重命名、删除，查看每个条件被哪些节点满足、是否已满足。
  - 完成后解锁：列出这个节点会满足哪些后继条件。
  - 会话链：当前会话高亮，已交接的可切回、可打开；显示上下文水位。
  - 勾选「项目里程碑」；里程碑标记显示在节点上方外侧、与卡片右对齐。
  - 执行设置（默认折叠）：Agent 预设，以及与 DSH 对话一致的「模型 + 推理强度」combobox。
  - 定时执行（默认折叠）：开关、cron、常用预设、下次执行时间、上次结果。
  - 危险操作（默认折叠）：归档整条会话链、删除节点（可勾选同时归档整条会话链）。
- **操作反馈**：新建、连边、改状态等操作的结果提示浮在中间画布栏的底部，出现和消失都不会推动画布或改变主视图的位置。
- **删除节点**有两种方式：`splice` 会把上游节点接到后继的前置条件上；`unlink` 只断开关系。失去全部满足者的条件会在结果里列出，提示你去补前置。

## 4. 用法举例

以一个 SSR 项目为例：数据清洗、模型训练、算法迭代、文档写作、服务部署同时推进。把它们建成一张图：

```
数据清洗 ─[训练数据就绪]→ 模型训练 ─[基线可复现]→ 算法迭代 ─[指标达标]→ 服务部署
   │                                                  │
   └─[数据说明完成]→ 文档写作 ←─[实验结论稳定]─────────┘
                       │
                       └─[部署文档完成]→ 服务部署
```

1. **拆任务**：数据清洗（已完成）、模型训练、算法迭代、文档写作、服务部署（待开始），再加一个「论文投稿 / 服务上线」里程碑。暂时没想清楚的任务先放「待规划」。
2. **连条件**：模型训练需要「训练数据就绪」；算法迭代需要「基线可复现」；文档写作需要「数据说明完成」和「实验结论稳定」；服务部署需要「模型指标达标」和「部署文档完成」。同一条条件可以由多个节点满足，比如数据清洗和一次补充实验都可以让「训练数据就绪」成立。
3. **看全局**：打开面板，项目概览显示 `1/6 完成 · 1 个可开始`。模型训练满足条件、可以开始；算法迭代被「基线可复现」阻塞；文档写作在等「实验结论稳定」；服务部署同时等两个条件，任一未满足都不可开始。
4. **推进**：在节点详情里给模型训练绑定合适的模型和推理强度，新建会话开跑。
5. **交接**：训练会话上下文超过 60%，点「交接新会话」——新会话只带 1–2k token 的简报，直接接着任务往下走；旧会话退休但保留，需要对照实验记录时可以切回。
6. **定时推进**：文档写作绑一条 `0 9 * * 1-5`，工作日早上自动检查进度并推进；如果节点还有未满足的前置条件、或当前会话正在跑，这次触发会跳过并记录原因。
7. **失败处理**：如果算法迭代跑失败，把它标成「已失败」并解除依赖，避免服务部署永远等一个不会完成的任务；随后补一个新节点来满足服务部署的条件。
8. **Agent 协作**：在训练会话里，Agent 通过 `graph_map` / `graph_next` 看到当前可做任务；你在对话里提出新需求时，它用 `graph_update_node` 更新任务描述。Agent 不能删节点、断边或改别人的会话，计划的安全边界始终由人掌握。

## 5. Agent 权限

插件注册 7 个工具，走工具而不是 HTTP（Agent 的 shell 调 HTTP 会被同源护栏挡住）：

| 工具 | 作用 |
|---|---|
| `graph_map` | 当前项目图：节点、五态、条件与满足情况、可做/阻塞/失败/待规划、里程碑、进度 |
| `graph_next` | 唯一最该做的那个可做节点 |
| `graph_add_node` | 新建节点（可带前置条件、预设/模型/推理强度） |
| `graph_link` | 让一个节点满足目标节点的某个前置条件（服务端环检测） |
| `graph_update_node` | 改标题 / 任务描述 / 五态 / 预设 / 模型 / 推理强度 / 失败时解绑 |
| `graph_add_condition` | 给节点单独添加一个前置条件 |
| `graph_attach_session` | 把当前会话挂到节点；节点已有别的当前会话时拒绝，让人去界面交接 |

**Agent 刻意不能做的事**（误判一次可能毁掉整张计划）：删节点、断边、删条件、归档会话、退休别人的当前会话、改里程碑、配置定时执行。

会话挂到节点之后，每一轮系统提示里会多出四行：当前节点、前置条件满足情况、完成后解锁什么，以及「用户提出新需求时用 `graph_update_node` 更新任务描述」的维护要求。

即使 Agent 没有实际调用工具，插件也会监听节点当前会话的 `user/message`，把最近 6 条用户请求以「## 对话需求（自动记录）」小节追加到任务描述末尾（交接/定时执行简报、斜杠命令和纯确认语不计入）。这是确定性的兜底，保证对话推进时任务描述至少跟着更新；Agent 仍可把有效内容整理进上方的正式描述。

## 6. 数据存储

```
<项目目录>/.dsh-task-graph/
├─ graph.json     # 唯一权威：节点、条件、边、会话链、revision
└─ events.jsonl   # 只追加的审计流（谁在什么时候改了什么）
```

- **随 git 走**：把使用插件的项目里的 `.dsh-task-graph/graph.json` 提交进仓库，团队共享同一张图。本仓库是插件开发仓库，它自己运行时写出的 `.dsh-task-graph/` 含有本机绝对路径和会话 id，已在 `.gitignore` 中排除，不随源码提交。
- **多窗口安全**：每次写入都带 `expectedRevision`，对不上返回 409 并提示刷新，不会互相覆盖。
- **原子写**：先写临时文件 → fsync → rename；先追加审计行再替换图文件。
- **损坏隔离**：`graph.json` 解析失败时改名为 `graph.json.corrupt-<时间>-<pid>` 并留一条警告，插件照常启动，不会因为一个坏文件打不开面板。
- **版本迁移**：当前 `schemaVersion: 2`。读到 v1 文档时会就地迁移：原来的收尾节点变成里程碑，每条旧的前序边变成一个独立条件（保持原来的 AND 语义），节点补上预设/定时字段，下一次提交写回 v2。

## 7. 代码结构

Host 半（Node）与浏览器半（浏览器）在同一个包里，靠 `package.json` 的 `dsh` 字段声明：

| 文件 | 作用 |
|---|---|
| `index.js` | Host 入口：装配 store / routes / tools / prompt / scheduler，每个面独立容错 |
| `src/model.js` | 纯函数：五态、条件派生、环检测、迁移、删除拼接、链不变量 |
| `src/store.js` | 图文件读写：revision CAS、按 workspace 串行、原子写、损坏隔离、订阅 |
| `src/ops.js` | 所有变更语义的唯一入口（HTTP 与工具共用同一条路径），含执行结算纯函数 |
| `src/sessions.js` | 会话适配：批量取事实、读尾部/事件、确定性简报、建会话、选模型、目录、归档 |
| `src/cron.js` | 无依赖 5 段 cron 解析与下次执行时间计算 |
| `src/scheduler.js` | 每节点定时执行：扫描、跳过规则、启动、执行结果结算 |
| `src/services.js` | 可选服务的读取（`ctx.get` 不受 `inject` 限制，直接 `ctx.xxx` 会抛错） |
| `src/routes.js` | `GET /state`、`/workspaces`、`/catalog`、`POST /action`、`GET /events`(SSE) |
| `src/tools.js` | 7 个 Agent 工具 |
| `src/prompt.js` | 每轮注入的四行节点上下文与任务描述维护要求 |
| `src/description.js` | 监听当前会话的用户消息，自动把最近请求回写到任务描述 |
| `src/workspaces.js` | workspace 解析（含 `cwd` 兜底匹配） |
| `client.js` | 浏览器半：单文件模块，注册 `main` 面板与侧栏入口，手写 SVG 画布 |
| `test/` | `node:test` 单元与集成测试 |

**没有构建步骤**：Host 是普通 ESM；浏览器半是手写的 `window.__ModuleLoader__.load(...)` 模块，只从平台种子表取 `react`，因此改完代码不需要 tsc/tsdown。插件目录在 profile 之外，所以**不要**在插件代码里 import `@deepseek-ai/*`（解析不到，会把插件变成加载失败）。

## 9. 边界（明确不做）

- 没有「删除会话」：DSH 只有归档。删节点时可选择归档其会话链，归档可恢复。
- 不做跨项目依赖、关键路径、模板批量建图。
- 定时执行只处理「单节点的一次会话」，不做多节点编排/流水线；权限提升仍要人工确认，插件不会静默提权。
- 定时执行是尽力而为：执行会话在运行中被删除时只记录结果、不自动改节点状态；会话已空闲但事件里没有 `turn/end` 时会继续等待跟踪。遇到这两种情况需要人到界面上把节点改回「待开始」或「已失败」。
- 画布是手写 SVG，不做框选、不做上千节点虚拟化。
- 自动布局是分层启发式：尽量消除可避免的边交叉，但不保证全局最少交叉；手动位置不会被自动覆盖，只有点「自动布局」才会清除手动位置。拖动避让只处理节点矩形之间的重叠，不重排整张图。
- 网格布局使用固定的 320×198（约黄金比例）网格，不提供自定义格子尺寸。
- 任务描述的「对话需求（自动记录）」小节是确定性兜底，最多保留最近 6 条用户请求，不做语义摘要；真正整理需求仍由人或 Agent 改写上方描述。自动记录只跟随节点的当前会话，退休会话不参与。
- `main` 面板切走即卸载；视口、选中态、三栏宽度、布局模式与任务描述高度存在 `localStorage`，切回来会恢复。
- 浏览器 bundle 热重载会让 `main` 注册表短暂变化，ui-layout 因此回退到对话；插件会记住「用户当时在任务图谱面板」并在重新注册后恢复一次。用户主动切回对话时不会触发恢复。
- 交接简报是确定性抽取；模型摘要留到后续版本。
