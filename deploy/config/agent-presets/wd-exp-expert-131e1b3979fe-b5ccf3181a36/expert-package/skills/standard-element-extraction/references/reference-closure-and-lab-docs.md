# 引用闭包与实验室文件接入

两份补充材料决定规则能不能落地：**标准引用的文件**（判据来源）与**实验室自己的文件**（执行依据）。缺任何一层，审核都只能停在「按标准应该」而不能回答「按你们的规定做了没有」。

## 一、引用闭包

### 1. 引用来源

| 来源 | 是否纳入 | 说明 |
|---|---|---|
| 第 2 章 规范性引用文件 | 必须 | 逐个登记，递归展开 |
| 正文中的「见/按/参照/应符合 + 标准号」 | 必须 | 如「见 GB 11893」「按 HJ/T 91 和 HJ/T 164 的相关规定」 |
| 图注、表注中的标准号 | 必须 | 影响参数或方法的，按引用处理 |
| 公告、前言、参考文献中顺带提到的标准号 | 不扩围 | 登记为背景，写明「不构成要求」的理由 |
| 同族方法标准（如 HJ 670） | 登记到方法族 | 不自动纳入规则，除非报告声明使用该方法 |

### 2. 递归规则

1. 一级引用（本标准直接引用）必须覆盖；未上传即 PENDING_UPLOAD。
2. 被引用文件上传后，解析它自己的规范性引用，形成二级引用；若其内容影响判定（如干扰消除方法、采样规范），继续展开；纯定义性或资料性引用可止步并说明理由。
3. 每层登记 depth、referenced_by（引用链）、affected_clauses、affected_rules。
4. 深度不设硬上限，但每层必须回答「它是否改变某条规则的判定」；不改变的记录为「已阅，不影响判定」。

### 3. 待上传提醒（标准话术）

> 本标准第 2 章及正文引用了以下文件，当前未提供，相关要求暂无法完整判定：
> - GB 11893《水质 总磷的测定 钼酸铵分光光度法》——被 4.1 引用（砷、铬、硫干扰的消除方法），影响规则 ARC-C1-04.1-01。
> - HJ/T 91《地表水和污水监测技术规范》——被 7 引用（样品采集与保存），影响 C2 类规则。
> - HJ/T 164《地下水环境监测技术规范》——被 7 引用（地下水样品采集与保存），影响 C2 类规则。

提醒必须写到「影响哪些规则」，不能只列文件名。

### 4. HJ 671—2013 的引用实例

| 引用 | 被引条款 | 引用内容 | 当前状态 | 影响 |
|---|---|---|---|---|
| GB 11893 | 4.1 | 砷、铬、硫干扰的具体消除方法 | PENDING_UPLOAD | 干扰消除规则无法细化 |

## 二、实验室文件接入

### 1. 文件类型

| 类型 | 作用 | 典型内容 |
|---|---|---|
| SOP / 作业指导书 | 把标准步骤落到本实验室 | 仪器型号、进样顺序、参数设置、人员分工 |
| 质控规程 | 落实质控频次与判定 | 空白、平行、加标、质控图、超限处理 |
| 仪器说明书 | 把「按说明书」具体化 | 泵速、进样体积、反应圈、加热温度、维护周期 |
| 记录表单 | 审核的证据载体 | 原始记录、前处理记录、试剂配制记录、温湿度记录 |
| 样品流转文件 | 证明样品链 | 交接单、保存条件记录、时限记录 |

### 2. 对齐状态

| 状态 | 判据 | 规则处理 |
|---|---|---|
| IMPLEMENTS | 内部文件条款与标准要求一致 | 规则锚标准，执行依据指内部条款 |
| STRICTER | 内部更严（如每批 3 个空白） | 按内部执行，source_layer=LAB_SOP，注「严于标准」 |
| LOOSER | 内部更松（如每批 1 个空白） | CONFLICT_PENDING，不得按松的判通过 |
| CONFLICT | 与标准矛盾（如保存温度不同） | 并列原文，交技术负责人确认 |
| MISSING | 标准有要求、内部未落地 | 标待补；规则仍按标准判 |
| EXTRA | 内部额外要求 | 作为 C8 检查项，不冒充标准条款 |
| PENDING_DOC | 内部文件未上传 | 规则按标准判，标「内部落地待核」 |

### 3. 仪器说明书的作用

标准里常见的「按仪器说明书设定工作参数」「不同型号可参考本标准选择仪器条件」属于 **GAP-EXTERNAL**：不补说明书，参数就只能停在「按说明书」这一层，无法核对具体值。

说明书上传后，把以下参数落到数值并登记来源：泵速、进样体积/时间、反应圈长度、加热池温度、UV 灯状态、检测波长与光程、基线稳定时间、清洗程序。

### 4. 优先级与冲突

1. 标准 MUST 与内部更严：按更严执行（可审核通过，但注明内部更严）。
2. 标准 MUST 与内部更松：按标准执行，内部文件标 LOOSER，提整改建议。
3. 标准 SHOULD 与内部 MUST：按内部 MUST（自愿加严）。
4. 内部文件之间冲突：以生效日期新、适用范围匹配者为准，并标 CONFLICT_PENDING 待确认。
5. 任何情况下不得用「内部没规定」作为标准要求不成立的理由。

### 5. 过程文档映射

规则必须能指向具体过程文档与字段，否则审核只能看报告结论：

| 过程环节 | 文档 | 常见核对字段 |
|---|---|---|
| 采样 | 样品流转单、采样记录 | 容器、固定剂、pH、时间、温度 |
| 前处理 | 前处理记录 | 消解/中和、稀释倍数、过滤 |
| 校准 | 校准曲线记录 | 浓度点、信号值、回归方程、γ |
| 测定 | 仪器使用记录、原始记录 | 仪器编号、参数、峰面积、基线 |
| 试剂 | 试剂配制记录 | 批号、浓度、配制日期、有效期 |
| 质控 | 质控记录 | 空白、平行、加标、质控样、系统性能 |
| 报告 | 检测报告 | 依据、结果、单位、修约、检出限 |

## 三、方法族对照

同一被测物的多个方法标准放在一张表里，只用于「选规则集」与「标差异」，不合并参数。

| 字段 | 说明 |
|---|---|
| analyte / matrix | 被测物与适用基质 |
| standards | 标准号与版本 |
| principle / digestion | 原理与消解方式 |
| DL / range / cell | 检出限、范围、光程与波长 |
| key reagents | 关键试剂 |
| QC indicators | 质控指标 |
| result expression | 结果表示 |
| rule_set_id | 规则集 ID |
| diff_notes | 与其他方法的差异 |

未上传的方法只登记标准号与「待上传」，不填任何数值。报告声明哪个方法，就只套哪个规则集；跨方法混用参数视为抽取错误。
