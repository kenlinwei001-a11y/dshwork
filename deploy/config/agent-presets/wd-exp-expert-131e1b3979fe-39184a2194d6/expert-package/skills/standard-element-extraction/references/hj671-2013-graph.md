## 7 算子（graph schema 1.1）

| 算子 | 方向 | 含义 |
|---|---|---|
| specifies | 条款 → 要素/规则 | 该条款规定了该要素/规则 |
| checks | 规则 → 字段 | 规则核对哪个文档字段 |
| gates | 规则 → 结果/批次 | 质控门约束结果有效性 |
| bounds | 规则 → 结果 | 适用边界约束判定 |
| requires | 步骤 → 设备/试剂/前序 | 执行依赖 |
| precedes | 步骤 → 步骤 | 先后顺序 |
| computes | 公式 → 结果 | 公式产出结果 |
| cites | 条款 → 引用文件 | 规范性引用 |
| affects | 引用/缺口 → 规则或条款 | 未上传或冲突影响范围 |
| applies | 方法 → 规则集 | 报告声明方法后选规则集 |
| contains | 规则集 → 规则 | 规则集成员 |
| annotates | 注 → 条款 | 注对条款的补充 |

traces / invalidates / aligns 保留给证据回指、失效传播与实验室文件对齐视图；本标准图谱暂未使用，使用时不得改变已有节点 ID。

## 8 页面与审核专家怎么用

1. 报告声明方法（HJ 671—2013）→ method 节点 → ruleset → contains 取 39 张规则卡。
2. 每条规则：checks 取字段与定位策略；anchor 取条款页码；gates 取结果联动。
3. 待上传引用（REF-01/02/03）走 affects 取受影响规则；页面显示「待补依据」，不显示通过。
4. 视图片段已写入 JSON 的 views 字段（overview / procedure / dependency / coverage_11_2 / pending_refs），页面可按 view_id 直接取子图。
5. 图谱只读；审核结果写入独立的结果记录，不修改图谱。

## 10 维护

- 标准换版：条款 ID 不变则图增量更新；新增/删除条款先改 clause 节点，再改要素与规则边，最后跑一次覆盖校验。
- 引用文件上传：把 REF 节点 status 改为 PROVIDED，补二级引用节点，affects 边改为实际影响，不重建全图。
- 实验室文件接入：新增 lab_doc 节点与 aligns 边，挂到对应要素；不改标准侧节点。
- 新增规则：rule 节点 + specifies（条款）+ checks（字段）+ gates/bounds（如适用），并更新 ruleset contains。
