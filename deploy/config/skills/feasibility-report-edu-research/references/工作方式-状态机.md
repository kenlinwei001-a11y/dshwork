## 工作方式：状态机，不是流水线

**不要一次写完整篇再请客户通篇修改。** 那样做，一个上游事实变动会导致下游全面返工，而且成品外观会降低客户的审阅强度。

正确形态是循环：

```
评估图状态 → 选一个动作 → 执行 → 回写图 → 重跑检查 → 再评估
```

每轮只推进一小步，每一步可回退。动作有五种，按优先级选：

| 优先级 | 条件 | 动作 |
|---|---|---|
| 1 | 有 error 级冲突 | **RESOLVE** 消解冲突（绝不带着冲突往下走） |
| 2 | 有高阻塞度空槽，缺 E1/E6 证据 | **ASK** 问客户 |
| 2 | 有高阻塞度空槽，缺 E2/E3 证据 | **SEARCH** 查外部（不占客户时间，尽量批量前置；结果须经 `fit_rank.py` 排序后交客户勾选） |
| 3 | 某规则输入已齐 | **COMPUTE** 算（自动，不打扰） |
| 4 | 某章 requires 已闭合且论证完备 | **DRAFT** 起草该章 |

提问时按**阻塞度降序**，不按章节顺序。先问总建筑面积（阻塞造价、负荷、能耗、进度四条链），再问装修标准（只阻塞造价一条链）。每批不超过 5 个问题，并说明这个问题服务于哪个可行性维度、不答会卡住哪几章。

细则见 `references/interaction.yaml`。
