## 读包时判冲突：`caliber_check`（可执行）

**读包最容易犯的错：把「口径差异」当成「算错了」。**

### 三个数的差别

```
客户报 6,780  规则算 9,350  差 +2,570

没有口径信息 → 只能标「冲突待审」
有口径信息   → 可以判「疑心口径差异：规则含装饰装修，客户不含」
```

### 可执行调用

```python
from corpus_pipeline.caliber_check import classify_conflict

r = classify_conflict("土建工程", provided=6780, recomputed=9350, fsm=fact_source_map)
# {
#   'kind': 'caliber_difference',
#   'confidence': '推测，待客户确认',
#   'delta': 2570.0,
#   'reason': '规则值高于客户值 → 规则含装饰装修/外立面/装配式增量',
#   'suggested_calibers': {'provided': '不含装饰装修', 'recomputed': '含装饰装修'},
#   'action': '登记为**疑似口径差异**；正文须同时写出两侧口径与数值'
# }
```

### 判据来自哪里

`fact_source_map.yaml` 的 `mapping` 字段（口径锚定）：

```yaml
- fact: 土建工程
  mapping:
    calibers: [含装饰装修, 不含装饰装修]
    default: 不含装饰装修
    semantic_filter: 仅结构与砌筑，不含室内装饰、外立面、装配式增量
    grain: 按单项工程
    canonical: true
```

**有 `mapping` 才能判口径；没有就只能判冲突。**

### 三级置信度，都不得据此认定某个值正确

| 级别 | 含义 | 能否据此定值 |
|---|---|---|
| **确定** | 客户明确说了口径 | 能 |
| **推测，待客户确认** | 按领域常识推断 | **不能** |
| **待确认口径** | 有口径位但方向不在已知清单内 | **不能** |

**正文写法（硬要求）**：

```
✗ 总投资 11,800 万元（错误做法：只写一个数）
✓ 总投资 11,800 万元；客户报表口径含暂列金，规则重算口径不含，
  差 X 万元 —— 口径待客户确认（疑似口径差异，非计算错误）
```

### 一个诚实的边界

`KNOWN_DELIBERATE` 里的方向与口径对**是领域常识推测，不是客户确认过的**。
所以任何 `caliber_difference` 都只是**"疑似"**，不能当结论用。
