## 标准引用链：三层库 + 四类引用（v1.5 新增）

**技术标准不写死在规则里**。规则只存引用，内容在库。

### 三层

```
L1 标准库   lineage/mock-standard-db.yaml
             standards(code) / clauses(clause_id = code#clause_no) / limits(limit_id)
L2 函数库   functions/derivation_templates.yaml
             expr 里用 {limit@<code>#<clause_no>} 引用限值
L3 因果库   lineage/causality-db.yaml
             causality(from, to, mechanism, clause_id) —— 回答「改一个会怎样」
```

**三层之间只传 ID**：`code` / `clause_id` / `limit_id` / `rule_id`。

### 当前状态（v1.5）

| 层 | 状态 |
|---|---|
| L1 目录级 | 17 标准 / 54 条款骨架 / 21 限值位 |
| L1 数值 | **0 个有值（全待抽）** |
| L2 | 35 规则；3 条判定规则已用 `{limit@...}` |
| L3 | schema 已定，**空表**；direct 类可从 computed_from 机械生成（103 条） |

**关键**：`limit.value` 为 `null` 时，规则应标 `UNDEFINED（限值待核）`，**不得用默认值**。

### 四类引用不得混用

| 类型 | 指向 | 语义 |
|---|---|---|
| `bounded_by` | 技术标准条款 | 限值/计算依据 |
| `grounded_by` | 政策文件 | 合法性依据 |
| `constrained_by` | `ontology/constraints.yaml` | 业务口径约束 |
| `supported_by` | `evidence` | 佐证材料 |

**混用后果**：写作时无法区分「法定要求」还是「参考案例」。

### 读包时的三步

```
① 读 FILE-INDEX.yaml → 找 lineage/mock-standard-db.yaml 的条目
② 按 clause_id 取条款；text 为 null → 该条款未抽，不能引用原文
③ 按 limit_id 取限值；value 为 null → 相关规则标「限值待核」
```
