# Knowledge Generalization Skill

## Skill ID
SK-14

## Purpose
从历史项目中提取可复用 Ontology、Reasoning Pattern、Claim Pattern、分析框架和规则，同时隔离项目专属事实。

## 何时使用

调用条件：已有已完成项目资产与复用边界说明。
- 典型请求：沉淀方法论｜把经验抽成可复用规则｜做成模板给下个项目用
- 不要在此调用：搬运项目数值与专有事实

## 边界与不适用

- 不做：绝不跨项目复制项目专属事实与数值
- 不做：只复用结构与规则
- 不做：没有明确复用策略时不落地
- 缺输入：先有已完成的项目资产与复用边界说明

## 产出物必须是四层，而不是一份规则快照（v2 增补）

| 层 | 文件 | 内容 | 验收 |
|---|---|---|---|
| **L0 量位目录** | `rules/quantity-catalog.yaml` | 从大纲 must_cover + 标准算式 + 历史报告归纳出「该算哪些量」 | 量位覆盖下一项目的 must_cover ≥90% |
| **L1 算子与换算** | `rules/operators.yaml` | SUM/DIFF/SCALE/CAPACITY/CONVERT/CHECK + 单位换算表 | 规则可拆成算子组合，不再散落自由表达式 |
| **L2 标准条款** | `standards/index.yaml` | 标准号#条款 → value/unit/status（已录入/待抽取） | 形包引用的每个 `limit@…` 都能解析或标待抽取 |
| **L3 项目特化规则** | `functions/derivation_templates.yaml` | 单个项目用到的算式 | 每条规则带 target/deps/operator/unit/section304/source/status |

只做 L3 = 项目快照，不是可复用规则库。

## 规则构建工序（必须执行，不能作为副产品）

1. **枚举量位**：304 大纲每节 must_cover → 量位；标准条款 → 量位；历史报告数字 → 量类；
2. **注册规则**：每条规则登记 `id/target/deps/operator/unit/section304/source/status`；
3. **闭包校验**：量位 × {规则, 事实, 标准条款} → 缺口清单；缺口不为 0 时不得宣称形包完成；
4. **多项目回归**：至少 2 个不同项目（不同行业更好）跑通，规则命中率与无源数字纳入验收。

## 反模式（本项目实测）

- 把「上财报告里出现过的算式」当成规则全集 → 换项目立刻缺 15,120 / 3,880 / 1,558；
- 只给 `limit@标准#条款` 引用、不给 limit 值表 → 14 条引用全为 null，条件规则永远算不出；
- 规则用自由字符串 expr、无算子层 → 无法做闭包、无法跨项目复用；
- 验收只看「回放能复现」→ 单项目通过即误判可复用。

## 验收指标（写进产出报告）

- L0 量位闭包率 100%（每个量位有规则/事实/标准路径）；
- L2 limit 解析率 = 100%（或显式标待抽取并给出所需原件）；
- 跨项目回归：≥2 项目，规则命中率 ≥90%，正文无源数字 = 0。
