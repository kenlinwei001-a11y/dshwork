# Entity Extraction Skill

## Skill ID
SK-03

## Purpose
从文本中抽取企业、基地、车间、产线、客户、材料、供应商等实体及其 mention。

## Input
- `project_id`
- `document_id`
- `version_id`
- 上游 Skill 输出
- 原文或结构化中间结果

## Output
必须输出稳定 ID、结构化结果以及 provenance/来源关联字段。

## Execution Rules
1. 只使用输入中存在或可由明确规则推导的信息，不编造事实。
2. 所有结果尽可能绑定 `project_id`、`document_id`、`version_id`。
3. Fact、Claim、Evidence、Reasoning 必须保留来源链。
4. 发现冲突时输出冲突状态，不擅自裁决。
5. 不得在没有复用策略的情况下跨项目复制项目专属事实。

## Validation
使用 `tests/golden.json` 和 `tests/expected.json` 执行基础验收。


## 两类必须补的实体：数值实体 · 判断句实体

原有清单（企业/基地/车间/产线/客户/材料/供应商）**漏了两类关键实体**，实测一个可研项目：
数值实体漏抽 52 个、判断句里的判断主体一个没抽。

### 一、数值实体（含数值的实体）

**定义**：主体 + 数值 + 单位 三元可核验的存在。

```
总建筑面积 = 18319 ㎡        ← 实体「总建筑面积」
就业率 = 95 %                ← 实体「毕业生就业率」
水泵扬程 H = 75 m            ← 实体「50AABH12-15*5 泵」
```

#### 识别模式

```python
UNITS = ["㎡/人","㎡","m²","m³/d","m³/h","m³","kN/m²","W/㎡","kW·h","kWh",
         "kW","kVA","L/s","L/min·㎡","L/人·日","L/生·日","万元","元/㎡","元",
         "万人","人","台","套","间","个","米","m","层","度","%","‰","d","天","小时","h","年"]
NUM_RE = r"(?<![\d\.\-])(\d{1,3}(?:,\d{3})*(?:\.\d+)?|\d+(?:\.\d+)?)\s*(单位)"
```

#### 必须排除的无效数字（这一步比识别更重要）

实测 398 个候选里，**105 个是无效数字**，直接建节点会污染图谱。

| 类型 | 例子 | 排除依据 |
|---|---|---|
| **章节号** | `6.4.2` `§5.6` | 上下文含「第N章/节/条款/见表/附录」 |
| **条款号** | `5.1.1` `3.3.1-4` | 同上；或形态为 `\d+\.\d+\.\d+` |
| **页码** | `- 12 -` | 单独成行且无单位 |
| **年份/日期** | `2019年` `2020年7月` | **时间点不是可计算数值**（除非语境是「工期/使用年限/工作天数」） |
| **序号** | `1.` `2.` `（3）` | 无单位 + 1~2 位整数 |
| **标准编号** | `GB50016-2014` | 前缀 `GB/JGJ/DGJ/建标` |
| **文号** | `〔2019〕5号` | 前缀 `〔` |
| **电话/邮编** | `021-6590xxxx` | 含 `-` 且长度≥7 |

#### 时间点 vs 时长（最容易错）

```python
TIMEPOINT = r"(19|20)\d{2}\s*年|\d{1,2}\s*月\s*\d{1,2}\s*日"
DURATION  = r"(工期|使用年限|设计年限|寿命|周期|年限|期限|工作天数|延续时间|小时数)"

unit in ("年","月","日") and not DURATION.search(ctx)  → 排除（时间点）
unit in ("年","月","日") and     DURATION.search(ctx)  → 保留（时长）
```

| 原文 | 判定 |
|---|---|
| 本项目预计于 **2020 年**开工 | ❌ 时间点 |
| 建设工期约为 **24 个月** | ✅ 时长（可算进度） |
| 设计使用年限 **50 年** | ✅ 时长（可判合规） |

### 二、判断句里的实体

**定义**：句中有判断词时，句子涉及的主体、对象、依据都要抽为实体。

**为什么单列**：判断句的实体与陈述句不同 —— 陈述句抽「是什么」，判断句要抽「谁在判断什么」。

#### 判断词四族（决定抽什么）

| 族 | 词 | 要抽的实体 |
|---|---|---|
| **结论** | 充分、合理、必要、可行、良好、有利、显著、可控、的需要 | **判断对象**（建设必要性/建设规模/资金来源） |
| **建议** | 建议、宜采用、推荐 | **建议对象 + 建议动作**（有关部门/尽早批复） |
| **预测** | 可能、预计、力争、届时、将达 | **预测指标 + 目标值 + 时点**（一流学科/2025年/ESI前1%） |
| **推理** | 由于、导致、从而、因此 | **前提 + 结论**（校区设施老化 → 教学条件不足） |

#### 抽取规则

```
判断句 → 抽三类实体：
  ① 判断主体：谁做判断（编制方/评审方/标准）
  ② 判断对象：判断什么（建设必要性/规模合理性/资金保障）
  ③ 判断依据：凭什么（政策文件/数据/规范）—— 常为空，空即记缺口
```

**实测**：一句「建设必要性充分：项目的建设是提升我国新兴领域科研水平…的需要」

| 抽什么 | 结果 |
|---|---|
| 判断主体 | 编制方（隐含） |
| 判断对象 | 建设必要性 |
| 判断依据 | 《中共中央关于制定…五年规划》（cites） |

#### 判断句实体必须带可证伪性

```yaml
claim:
  text: 建设必要性充分
  subject: 建设必要性          # 判断对象（实体）
  claim_type: conclusion
  falsifiable_by: 找到一条证据表明该判断不成立
  evidence_refs: [REF:《中共中央关于制定...》]
```

**说不清「什么能推翻它」的，不是判断，是口号，不抽。**

### 三、实体抽完之后必须做的三项检查

| 检查 | 判据 | 不通过怎么办 |
|---|---|---|
| **数值可算性** | 有数值的实体，其一阶依赖（主体/单位）是否齐全 | 缺则记缺口，不建孤值节点 |
| **判断有据性** | 每条判断句实体，其 `evidence_refs` 是否非空 | 空则标「报告缺证据」，不改原文 |
| **无效数字拦截** | 建节点前跑一遍排除规则 | 命中任何一条即不建 |

### 四、实测数据（某可研项目）

```
全文候选数值      398 个
排除无效          105 个（年份 68 / 章节 22 / 序号 9 / 其他 6）
有效数值          293 个
已建节点          247 个
漏抽               52 个
```

**52 个漏抽里**：

| 性质 | 条数 | 该不该建 |
|---|---|---|
| 设备参数（水泵 Q/H/N） | 24 | ✅ 建，但需结构化为「设备→参数」 |
| **规范要求**（无障碍尺寸） | 12 | ❌ 不建 —— 是「要求」不是「取值」 |
| 项目参数 | 5 | ✅ 建（注意单位错：180 m 实为 180 mm） |
| 表格数值 | 5 | ⚠️ 人工确认 |
| 时间点 | 6 | ❌ 不建 |

**关键区分**：

> **规范要求 ≠ 项目取值。**
> 「无障碍电梯候梯厅深度 >1.8m」是《无障碍设计规范》的强制要求，
> 不是本项目的设计值。建 fact 会把「要求」和「取值」混为一谈。

### 五、一条铁律

> **数值实体不是「有数字就算」，而是「主体+数值+单位三者可核验才算」。**
>
> 章节号、条款号、年份、序号都是数字，但都不是实体。
> 判错一个，图谱里就多一条脏数据；漏一条，下游推演就算不出来。

## 工序（四段式）

> **识别模式、UNITS 清单、无效数字排除表都在上一节「两类必须补的实体」里**（140 行，已详述）。
> 本节只加**可校验的契约**与**门禁**，不重复那边的识别规则。

