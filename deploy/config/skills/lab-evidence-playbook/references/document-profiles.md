# 文档类型 Profile（抽取逻辑的差异都在这里）

同一个抽取专家、同一套"定位→填槽→记 span"机制；**不同文档的差异体现为 profile**，不是新专家。
每个 profile 规定：字段清单、定位策略、置信度门槛、常见坑。

## 通用规则

- 所有字段必须有 `page + quote`；quote 必须能在该文档中检索命中。
- 定位策略四选一：`table_cell`（表头+行列）、`field_label`（标签:值）、`checkbox`（勾选项）、`ocr_hand`（手写/打印混合，仅 OCR 路线）。
- 扫描件置信度 < `min_conf` 的字段标 `unlocated`，不猜。

## P1 检测报告（report）

- 字段：报告编号、委托方、样品编号/数量、采样日期、接收日期、检测日期、方法声明（标准号+名称）、仪器、结果表（项目/值/单位/检出限）、结论、签字/章。
- 策略：结果表用 `table_cell`（表头必须含"项目/结果/单位"）；方法声明用 `field_label`（"依据"/"方法"）；签字用 `field_label`。
- 坑：单位在表头而非单元格；ND/<检出限 原样保留；方法声明可能写旧版年号。

## P2 委托单（entrust）

- 字段：委托方、联系人、样品类型、检测项目、时限、特殊要求。
- 策略：`field_label`；多项目时为列表，逐项成槽。
- 坑：项目名称与报告口径不一致（"总磷"vs"总磷（以P计）"）。

## P3 合同评审（contract_review）

- 字段：评审日期、方法可行性、人员/设备能力、分包项、结论。
- 策略：`checkbox` + `field_label`。
- 坑：评审日期晚于检测日期 → 记一致性标记，不判定。

## P4 任务单（work_order）

- 字段：任务号、样品数、项目、方法、检测人、计划完成日。
- 策略：`table_cell`（样品行）+ `field_label`。
- 坑：任务号与报告编号无关联字段时，用样品编号桥接。

## P5 样品流转单（chain_of_custody）

- 字段：样品编号、采样时间、接收时间、保存条件（温度/pH/固定剂）、交接人、状态。
- 策略：`table_cell` + `checkbox`（固定剂勾选）。
- 坑：温度写成区间或手写；"加酸至 pH≤2"可能只勾选不写值。

## P6 风险评估（risk_assessment）

- 字段：风险项、等级、控制措施、评估人/日期。
- 策略：`table_cell`。
- 坑：模板版本不同，列名不一，按语义匹配而非列序。

## P7 原始记录（raw_record）

- 字段：样品编号、称样量/移取体积、定容体积、稀释倍数、仪器读数、校准曲线（浓度点/信号/方程/r）、空白、平行、加标、计算式、检测人/复核人、日期。
- 策略：曲线用 `table_cell`（浓度/信号两列）；计算用 `field_label`（"结果"/"计算公式"）；签字用 `field_label`。
- 坑：曲线常数 a/b 可能只写方程；稀释倍数写在页脚；修改处无划改签名。

## P8 环境记录（env_record）

- 字段：温度、湿度、日期、记录人。
- 策略：`table_cell`（按日期的行）。
- 坑：区间值（20±2℃）；记录日期与检测日期不覆盖。

## P9 仪器运行记录（instrument_log）

- 字段：仪器编号、开机/关机时间、运行参数（流速/柱温/波长）、基线稳定时间、操作人。
- 策略：`field_label` + `table_cell`。
- 坑：仪器编号与报告附表不一致；参数写成"按说明书"。

## P10 校准证书（calibration_cert）

- 字段：仪器编号、校准日期、有效期、校准机构、证书号、结论。
- 策略：`field_label`。
- 坑：有效期覆盖检测日期需跨文档比对 → 只记事实，判定交审核。

## 与任务单的对应

`audit_tasks.jsonl` 的 `doc_type` 直接映射到 P1–P10；未匹配到 profile 的槽 → `missing_documents` 或 `unlocated`，不猜。
