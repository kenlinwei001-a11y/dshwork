# 认知锚

只在用户明确要求创建、读取、更新或复盘认知锚时加载本文件。认知锚是用户与模型维护的语义资产；插件和脚本只读状态与日期并提醒，不得改变命题、证据等级或生命周期。

## 生命周期

每条锚必须处于且只处于以下状态之一：

- `active`：仍可被后续事实升级、削弱或推翻；只有此状态参与日期提醒。
- `refuted`：具名事实推翻了原命题；保留原文和推翻履历，不删除。
- `realized`：命题所等待的事件已经兑现；记录兑现事实，不再作为待验证锚提醒。
- `archived`：不再服务当前决策，但没有被事实推翻或兑现；注明归档原因。

状态改变是模型在证据边界内的语义判断，并应得到用户请求或当前任务授权。代码只能识别并显示状态。

## 最小格式

在会话工作目录使用 `anchors/<主题>.md`；不要写入 Skill 安装目录。

```markdown
## A1：<可被一个事实更新的条件命题>

- 状态：active
- 证据边界：FACT / SINGLE_SOURCE / INFERENCE / HYPOTHESIS / NO_RESULT / INSUFFICIENT
- 当前依据：<原子主张卡或证据编号>
- 不能推出：<边界>
- 更新触发器：2026-09-30 <具名事件或材料>
- 检验履历：2026-06-30 建立 → <结果>
- 建立：2026-06-30
```

状态变更时追加履历：

```markdown
- 状态：refuted
- 检验履历：2026-12-31 <具名反证> → refuted
```

不要覆盖旧履历。需要保留审计痕迹时，在标题同时添加 `[refuted]`、`[realized]` 或 `[archived]`，旧格式 `[失效]` 视为 `refuted`。

## 更新协议

1. 先读相关主题文件与 `anchors/index.md`。
2. 用新证据重建原子主张卡，不从旧结论直接推状态。
3. 判断是保持 `active`、转为 `refuted`、转为 `realized`，还是因决策结束转为 `archived`。
4. 追加检验履历，更新触发器和证据边界；不删除历史。
5. 同步 `anchors/index.md`，可选在 `journal/decisions.md` 追加本次决定。

每主题活跃锚不超过 5 条。不可证伪的感想、永久正确的口号和普通笔记不要写成锚。

## 提醒边界

提醒器只读取 `active` 锚中的日期型“更新触发器”。无日期事件由人工复盘。错过的日期保持 overdue，直到模型/用户完成语义更新；代码不得滚动日期、自动升降级、创建新锚或把提醒当作行动授权。
