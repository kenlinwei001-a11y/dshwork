# 人工评分表与标准

每项 0–2 分；不确定就打 0 并在备注说明，不得给"印象分"。
`delivery.json`（机械合同）是评分的前置材料，不是评分本身。

## 交付轮（报告交付后立即打分）

| 编号 | 指标 | 2 分 | 1 分 | 0 分 |
|---|---|---|---|---|
| D1 | ①根结论强度与主张一致 | 根结论不超过 5 条，每条承重主张有卡，结论强度服从最弱主张 | 基本一致但个别结论超出最弱主张 | 结论与主张脱节或凭空拔高 |
| D2 | ②INSUFFICIENT 诚实性 | 所有未知/不足处明写 INSUFFICIENT 或"无法评估"，无"未找到→不存在"倒置 | 大部分诚实，个别缺口被轻描淡写 | 装懂：缺口被写成否定结论或伪造闭合 |
| D3 | ②观察与推断边界 | 每张卡区分观察到/可以推出/不能推出，含解释的整句不用 FACT | 边界大体清楚，个别卡混用 | 观察与推断大面积混写 |
| D4 | ③唯一下一验证 | 单一外部证据获取单元，且裁决一个承重分叉，成本最低 | 单一对象但裁决力弱或成本高 | 多个对象、不裁决分叉或只是"继续观察" |
| D5 | 机械合同 | `/resanity-report` 为 DELIVERY_READY 且无重大警告 | 有警告但人工确认可接受 | DELIVERY_INCOMPLETE 或忽略机械结果 |
| D6 | 红队质量 | 逐卡有具名最强反例且裁决理由成立；被证伪的主张确实降级/推翻；标注 self-countercase | 有反例行但个别敷衍或裁决理由不成立 | 无反例、反例与主张不相关或红队形同虚设 |
| D7 | 决策菜单可执行性 | 动作空间与证据边界匹配，每项所需证据明确可获取，条件式结论的升级/降级条件可判定 | 菜单存在但个别动作所需证据含糊 | 菜单缺失或动作与边界脱节 |

## 复盘轮（题目验证日到期后打分）

| 编号 | 指标 | 判定 |
|---|---|---|
| R1 | 每条承重主张的实际结果 | `confirmed` / `refuted` / `pending`（逐条列出，附具名事实与日期） |
| R2 | 被推翻主张的失效类型 | `tense`（时态/事件日期错）、`boundary`（证据边界过强）、`observation`（观察本身错）、`verification`（下一验证未能裁决分叉） |
| R3 | ①推翻率 | refuted 数 / 承重主张总数（分子分母都要写明） |
| R4 | 下一验证是否真的被执行 | 执行了且裁决了分叉 / 执行了未裁决 / 未执行 |
| R5 | 方法修订建议 | 依据 R2 的类型分布写一条具体协议修订（例：某类公告滞后 → EVENT_BY_DATE 更保守） |

```json
}
```

## 评分者校准

两名评审独立给同一题打分，D1–D5 逐项一致率低于 80% 时先对齐标准再继续，
避免把评分者漂移读成方法变化。
