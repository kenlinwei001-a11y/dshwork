# 前向推演模式（Forward Deduction Patterns）

「推演」= 在语义图谱的依赖图上做**正向传播**，从 facts 出发，经 reasoning 派生新结论，
再聚合为 claims。推演结果作为写作的骨架。本文档定义可复用的推演范式。

## 1. 构建依赖图

推演前先把图转成可遍历的依赖结构：

- **facts** 是叶子节点（不可再分解）。
- **reasoning** 是中间节点：`inputs → reasoning → output`。
- **claims** 是高层节点：`deps → claim`，`deps` 可指向 facts / reasoning / claims。

建立两张邻接表：`pred[node]`（谁依赖它）与 `succ[node]`（它依赖谁）。凡 `conflict` 字段
非空的 reasoning/claim，标记为「污染节点」。

## 2. 拓扑排序确定推导顺序

对 reasoning 与 claims 求拓扑序：只在其所有 `inputs`/`deps` 已求值后，才处理该节点。
遇到环（A 依赖 B 且 B 依赖 A）时显式报出，不得强行展开。

## 3. 正向传播规则

| 节点 | 动作 |
|------|------|
| fact | 直接取值，记录 `(value, unit)` |
| reasoning | 代入 `inputs` 的已求值结果，按 `formula` 计算 `result`；若带 `conflict`，结果标记「待审」 |
| claim | 依据 `deps` 的求值结果与 `evidence` 的性质，确定可陈述性 |

**派生新结论**：当多个 fact/reasoning 的组合能推出图谱中尚未明示的结论时，可**新增**
一个推演结论，并显式标注其 `deps` 与证据链（不得捏造事实，只能重组已有事实与计算）。
新增结论在报告中标记为「推演结论」而非「原始事实」。

## 4. 口径与单位校验（推演硬约束）

- 相同单位的量才能相加/相减；流量（`/月`）与存量（总量）**不可**直接相减。
- 换算须显式写明换算率，并把换算来源绑定证据。
- 每个派生数值都要能由 `formula` 反推，无法反推的数值视为待审。

典型反例（来自 PX-2026-001 的 CF1）：`39 GWh/月(流量) − 34 GWh(存量) = 5 GWh/月`，
口径错误。正确的推演应先换算成同口径（如总需求 117 GWh vs 库存 34 GWh），再比较。

## 5. 冲突处理（待审，不裁决）

推演遇到 `conflicts` 中涉及的节点时：

1. 不在正文给出「确定」结论，改为「待审」方框，原样转述 `description`。
2. 标注受影响的 facts / reasoning / claims（`involved`）。
3. 若该冲突影响下游结论，对下游结论同样降级为「待审/附条件」。
4. 绝不自行修改数字或「补全」口径来消除冲突。

## 6. 情景分支（scenario branching）

`type` 为 `预测` 或带「情景」字样的 claim，须作为**并列情景**呈现，各自给出假设与结果，
不得合并成单一事实。每个情景标注其假设、依赖的事实、以及未决的不确定项。

## 7. 置信度分层

按 evidence `kind` 与 validation `status` 对结论分层表述：

| 组合 | 表述姿态 |
|------|----------|
| SUPPORT + 一手证据 | 陈述式（"为/是"） |
| PARTIAL_SUPPORT | 限定式（"在未计 X 的前提下"） |
| 仅预测/承诺证据 | 条件式（"若 S1 追加到货，则…"） |
| CONTRADICT | 转冲突/待审，不陈述 |
| CONTEXT（建议类） | 祈使式行动项 |

## 8. 推演结论登记

推演过程产生的每条新结论，登记为 `(结论文本, 依赖节点集合, 证据集合, 是否待审)` 四元组，
供「溯源写作」阶段逐条落到正文，避免推演与正文脱节。
