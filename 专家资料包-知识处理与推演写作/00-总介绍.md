## 4. 五者关系（一句话）

插件是安装与供货单元；技能、专家、MCP 连接、项目是插件管理的业务对象；项目把专家＋技能＋连接器组合成一次任务的能力快照，交给 Harness 原生 Agent 执行。

~~~text
DSH Profile（bundles + cordis.patch.yml）
  └─ 插件 plugin
       ├─ skills 插件      → N 个技能（怎么做）
       ├─ experts 插件     → N 个专家（谁来做），发布时把技能冻结成快照 + Agent preset
       ├─ connectors 插件  → N 个 MCP 连接（能连什么），按会话开放 mcp__<server>__*
       └─ projects 插件    → N 个项目（把三类 + 资料 + 任务组织起来）
                                   ↓ 新建任务：能力快照 + 配置修订
                          官方 Agent preset + MCP 工具命名空间
~~~

细节见 `01-关系总览/01-关系总览.md`。

## 5. 诚实边界

- 描述的是构建时刻的本机状态；会话里的实时观测来自运行时快照（时间见 `01-关系总览/02-数据来源与核对说明.md`）。
- 专家定义没有 MCP 字段；MCP 能力来自连接器，由项目或会话选择。
- 技能的 "已改动" 与 "已生效" 是两件事：已发布专家使用发布时冻结的快照，改库文件不改变已发布专家。
- 包内不含任何凭据；env 只留键名，URL 去 userinfo。
