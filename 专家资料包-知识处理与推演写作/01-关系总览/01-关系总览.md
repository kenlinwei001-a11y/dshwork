## 1. 分层模型

| 层 | 实体 | 拥有者 | 生命周期 | 本包目录 |
|---|---|---|---|---|
| 安装层 | 插件 plugin | DSH Profile 组合（官方 Loader） | 随插件安装/卸载；能力与界面一起出现或消失 | 05-插件/ |
| 能力层 | Skill | skills 插件 / 各插件资源目录 | 用户技能是普通目录，独立于插件；插件内置技能随插件 | 04-技能/ |
| 角色层 | 专家 / 专家团 | experts 插件 | 发布即冻结为不可变修订，编译成官方 Agent preset | 03-专家/ |
| 连接层 | MCP 连接（连接器） | connectors 插件（官方 MCP client + 官方凭据） | 全局或按项目作用域；按会话开放 mcp__ 命名空间 | 06-MCP/ |
| 组织层 | 项目 | projects 插件 | 只保存引用 + 配置修订，不复制领域数据 | 02-项目/ |
| 执行层 | 原生任务（会话） | Harness 官方 Agent / Session | 创建时固定能力快照与预设，运行中不被草稿改写 | 02-项目/ 任务表 |

## 2. 六条关键关系

### 2.1 插件 → Skill：可以携带，但不是同一种东西
- 插件把 Skill 正文放进自己的 resources/skills/<name>/SKILL.md，在 apply 时用 ctx.skills.register({ source: bundled, resourceBase }) 注册。
- 本机实例：workdsh-plugin-skills 内置 5 个（workdsh-ppt-design / word-design / excel-design / web-design / skill-creator）；workdsh-plugin-experts 内置 1 个（workdsh-expert-manager）。而这两个专家配备的 22 个 Skill 全部来自本机技能根 ~/.agents/skills/，不是插件内置技能。
- 判定：需要注册 Host 服务、提供 UI/路由/工具 → 插件；只是给模型的一套任务指令 + 参考 + 脚本 → Skill。

### 2.2 专家 → Skill：发布时冻结成快照
- 专家定义的 skill_requirements（上限 32 项）在发布时冻结为受管技能快照，与定义一起编译成官方 Agent preset（wd-exp-<kebab>-<digest>）。
- 因此：修改 Skill 文件不会改变已发布专家与已创建任务；需重新发布专家才会生成新的 preset 与修订。
- 本机实例：知识处理专家配备 21 个，推演写作专家配备 6 个，共享 6 个。

### 2.3 专家 ⇄ MCP：无直接关系
- 专家定义字段只有 skill_requirements 与 future_requirements，没有 MCP 字段；experts 插件整包源码中不存在 MCP 引用。
- MCP 能力来自连接器，由项目或会话选择后按 mcp__<server>__* 命名空间注入。
- 本机实例：知识处理专家与连接器「kp-mcp（知识处理工具层）」在项目配置中被并列选中，二者是同级引用，不是依赖。

### 2.4 项目 → 三者：只持有引用，创建任务时固定快照
- 契约固定能力类型：ProjectCapabilityKind = skill | expert | connector。
- 项目配置每保存一次生成一个不可变修订；任务创建时引用当时的修订，运行中不被后续修改影响。
- 项目不复制专家正文、Skill 正文或连接配置，只保存 kind + id + label + revision。

### 2.5 Skill → MCP：通过工具命名空间协作
- Skill 可以在正文或参考里指导模型调用 mcp__<server>__<tool>。
- 本机实例：knowledge-processing-toolchain 指向 kp-* 五组工具；graph-deductive-writing-skill 与 19 个「-skill」系列只依赖自身脚本与 schema，不依赖 MCP（逐项取证见 04-技能/ 各文档的「MCP 关联」）。

### 2.6 专家团 → 官方 Agent Teams
- 专家团成员引用各专家修订，运行时用官方九件套工具（spawn_teammate / send_message / list_agents / wait_agent / interrupt_agent / team_task_create / list / get / update），专家插件不自建调度器。
- 本机实例：这两个专家都是单专家，未配置 team，不涉及成员装配。

## 4. 常见误解

| 误解 | 事实 |
|---|---|
| 专家自带 MCP | 专家没有 MCP 字段；MCP 由项目或会话的连接器选择决定 |
| Skill 是插件 | Skill 是内容单元，不需要发 npm 包；插件可以内置 Skill，但二者不等价 |
| 项目拥有专家与 Skill | 项目只有引用；正文分别由 experts、skills、library 领域拥有 |
| 改了 Skill 就能改专家行为 | 已发布专家使用冻结快照，必须重新发布才生效 |
| 卸载插件会删掉技能 | 用户技能在技能根目录，卸载插件不删除；只有插件内置技能随插件消失 |
| 团队面板由专家插件实现 | 成员与共享任务由官方 Agent Teams 插件提供，专家插件只做资产与装配 |
