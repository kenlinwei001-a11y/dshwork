# graph-deductive-writing-skill · 参考 阶段-1建图

## 阶段 -1：从原始材料建图（新项目必读）

**当用户给的是 Word / Excel / PDF / Markdown 等原始材料、而不是已编译语义图谱时，
必须先执行本阶段**，产出的 `graph.json` 再作为「阶段 0」的输入。

### 支持格式与解析方式

| 格式 | 解析器 | 表格处理 |
|---|---|---|
| `.docx` | `python-docx` | 按 `<w:tbl>` **原生 grid** 读，不拍平 |
| `.xlsx` / `.xlsm` | `openpyxl` | 按 cell grid 读，保留 sheet 名 |
| `.pdf` | `PyMuPDF (fitz)` | 优先 `page.find_tables()`；取不到则只用文字层 |
| `.md` / `.txt` | 内置 | markdown 表格按 `\|` 切分，保列序 |
| `.csv` | 内置 | `csv.reader` |

**硬规矩**：表格必须读原生结构，**绝不把表格拍平成 markdown 再用正则猜列**。
拍平会丢列对应关系 —— 实测过一次拍平导致 110 个 subject 错乱。

### 三步

```python
# ① 材料 → provided_facts（确定性为主，零 LLM）
from corpus_pipeline.doc_facts import to_provided_facts
r = to_provided_facts("客户材料.docx", as_of="2026-03-15")
# r = {provided_facts, conflicts, warnings, stats}

# ② 借形 + 建项目图库
from corpus_pipeline.instantiate import instantiate_project
res = instantiate_project(
    corpus_dir=<历史语料包>,        # 由 library_find_analog 找到的最相似包
    project_dir="<新项目目录>",
    provided_facts=r["provided_facts"],
    meta={"project_id": "...", "title": "...", "data_cutoff": "..."},
)

# ③ 项目图库 → 语义图谱（八类节点）
from corpus_pipeline.graph_from_project import build_graph
g = build_graph("<新项目目录>", meta={...})
json.dump(g, open("GRAPH.json", "w"), ensure_ascii=False, indent=1)
```

### 读「形」包的顺序（拿到 zip 后先做这个）

> **完整读包协议见 `knowledge-asset-consumption` skill**（横切建图/审计/写作）。
> 本节只给写作场景的最短路径。

**不要全读 32 个文件** —— 先读索引，再按需取。

```
① 读 FILE-INDEX.yaml
      → 知道 27 个文件各有什么、主键是什么、10 条引用谁引用谁
② 按任务取最小集：
     要写某节       → templates/section-writing-guide-2023.yaml
     要某条规则     → functions/derivation_templates.yaml（唯一真理源）
     要规则依据标准 → lineage/standard-registry.yaml 的 rule_to_standard
     要事实的来源   → ontology/fact_source_map.yaml
     要事实是输入还是算出来的 → ontology/input_vs_derived.yaml
     要知道哪些坑   → ontology/known-defects.yaml
③ 引用一律按 ID/名称取，**不复制内容**：
     rules_required 里是 rule_id → 去 derivation_templates 取 expr
     不要在本地再存一份 expr（会漂移）
```

**FILE-INDEX.yaml 的关键字段**：

| 字段 | 用途 |
|---|---|
| `files[].what` | 这个文件是什么 |
| `files[].primary_key` | 按什么查（rule_id / fact / code / gate_id） |
| `files[].key_fields` | 里面有哪些关键字段、什么含义 |
| `files[].referenced_by` | 谁引用它 |
| `reference_graph[]` | 10 条引用的 from→to、类型、取数方式 |

**校验**：`reference_graph` 里 `to.file` 必须存在（悬空引用 = 0）。若发现悬空，先报告再继续。

### 节点标签从哪来（新规范）

形包里有两张标签表，但它们是**源项目的 116 个事实位**，新项目要用「第八道标注工序」重算：

```python
from corpus_pipeline.label_enrichment import enrich
enrich("<项目目录>")     # 给 graph/nodes.yaml 补 role / constraint_type / source_type / standard_id
```

**标注是确定性的**（结构判据，零 LLM）：

| 标签 | 判据 |
|---|---|
| `role` | 只做 dep → INPUT；只做 target → DERIVED_LEAF；两者都做 → INTERMEDIATE |
| `constraint_type` | INTERMEDIATE → SOFT_INPUT（双向求解）；DERIVED_LEAF → DERIVED；有 bounded_by 且 range_known=false → RETRIEVABLE；含「等级/是否」→ JUDGMENT；其余 → HARD_INPUT |
| `source_type` | 由 constraint_type 映射（HARD_INPUT→CUSTOMER 等）|
| `standard_id` | 从 bounded_by 关系的 payload.standard_id 或 source.standard 取标准号 |
| `solve_direction` | 仅 SOFT_INPUT 有：BOTH（客户可直给，也可由分项加总校验） |

**写作时的用法**：
- `HARD_INPUT` 缺值 → **必须问客户**，不得用行业惯例/同类项目值代替
- `RETRIEVABLE` 缺值 → 自己去标准/web 取
- `SOFT_INPUT` → 客户给了也**必须复算校验**，不一致登记待审
- `DERIVED` → **只能算，不能问客户要**

### gate 状态决定下一步

| `res["gate"]` | 含义 | 动作 |
|---|---|---|
| `PASS` | 无 undefined、无 replay_conflict | 直接进入阶段 0 |
| `REVIEW` | 有缺项或冲突 | **必须先向用户澄清**，不得直接出稿 |

### 缺什么就问什么，不许猜

| 情况 | 处置 |
|---|---|
| `undefined_notes` 非空 | 用右侧 spreadsheet 打开「遗漏补录表」，逐项请用户补；补齐后重跑 ② |
| `replay_conflicts` 非空 | 登记 `conflicts`，正文标「⚠ 待审」；**不裁决、不补数、不改口径凑平** |
| 单位与规则口径不一致（如 `m³` vs `万m³`）| 显式换算并记 `unit_conversion`，不得静默改值 |
| 同一名称出现多个值 | 进 `conflicts`，**不取其一** |
| 组织架构与历史包不同（如分中心改名）| 用历史包的名字提供值，或改语料包 deps；不可靠模糊匹配 |

### 与「借形不借值」的关系

本阶段严格遵循：历史语料包只提供**结构、规则、句式、模板**；
**所有数值只能来自用户材料**（`provided_facts`），不得从历史资产抄。

### 与既有工序的关系

```
用户材料（docx/xlsx/pdf/md）
   ↓ doc_facts.to_provided_facts       ← 本 skill 负责（阶段 -1）
provided_facts
   ↓ instantiate_project                ← 本 skill 负责（阶段 -1）
项目图库（nodes/rules/bindings/gate）
   ↓ graph_from_project.build_graph     ← 本 skill 负责（阶段 -1）
GRAPH.json（八类节点）
   ↓ validate_graph.py                  ← 阶段 0
推演写作（阶段 1–5）
```

**边界**：本阶段只做「材料 → 结构化事实 → 图谱」这个转换，
**不做深度语义抽取**（散落在长段落里的隐性事实仍建议先走
`document-parsing-skill` + `fact-extraction-skill`）。
