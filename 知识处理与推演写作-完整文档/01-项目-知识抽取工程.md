> 把历史稿件（docx/pdf/md）经七道工序，产出「语料包」，供写作 Agent 使用——
> 写作 Agent 只拿脱敏骨架 `skeletons.jsonl`，永远拿不到原文 `chunks.jsonl`。

## 二、七道工序 → 30 文件

```
1 归一化   → source/normalized.md, offset_map.json, assets/, original.<ext>
2 骨架抽取 → outline.yaml（章节层级 + 法定大纲覆盖校验）, meta.yaml
3 切块     → chunks/chunks.jsonl（语义边界，表格/图注独立成块）, embeddings.parquet
4 本体抽取 → graph/nodes|rules|relations|claims.yaml, evidence/*, provenance.yaml ※语义接 LLM
5 推演回放 → reasoning/derivation|decisions|trace（按规则重算、比对原值、检矛盾）
6 质量登记 → quality/conflicts|gaps|gate_report, graph/invariants.yaml（闸门）
7 脱敏索引 → chunks/skeletons.jsonl, index/node_index|term_index|signature, style/*（数值→{{node:Nxx}}）
```

## 三、30 文件契约（spec.py MANIFEST）

- **主存列是权威副本**，副本列是冗余拷贝，以主存为准。
- **Agent 访问形式**：① 注入（constraints/meta/outline/gate/style/terms）· ② 工具调用（corpus_get_chunk 等 10 个）· ③ 内嵌（conflicts/gaps）· ✕ 不对外（原文/整包/事件流）。
- **安全边界**：写作 Agent 只拿 `chunks/skeletons.jsonl`（数值已替换为 `{{node:Nxx}}` 占位符），数值单源存在图节点里；原文永不外发。

## 四、资产治理（知识处理侧 K0–K11）

1. **候选→正式状态机（P0）**：`manifest.status` 单向 `draft → validated → published`。抽取产物默认 draft，装配侧 `library_*` 检索默认不可见；经质量关口→validated；`publish`→published 才可检索/复用。禁止回退、禁止跳级。实现：`review.py` + `library.py` 过滤。
2. **资产依赖图（P1）**：16 域依赖（`dependencies.py`）。`impacted_assets(asset)` 沿依赖图正向传播：ontology 变更→全部 16 域；variable 变更→11 域，不误伤 report_structure。含依赖闭包与环检测。
3. **三质量关口（P1）**：QG1 来源可信度（K1–K3：文档版本/来源指纹/切片锚点）；QG2 语义完整性（K4–K7：Claim 合法、关系 from/to/type、证据有来源）；QG3 资产可复用性（K8–K10：16 域装配方法齐全、依赖图无环、约束存在）。
4. **知识 ≠ 能力双路径（P2）**：`registered`（带 formula/expr/code/function 可执行证据→真实能力）；`induced`（仅描述/模式→候选方法，不能当生产级能力）。函数库、Skill、DAG 不能从历史报告文本可靠「抽取」。
5. **SourceAnchor + 跨文档实体注册表（P2）**：`validate_source_anchor`（document_id 必填 + table_cell/char 精确定位）；`EntityRegistry`（register/resolve/add_mention，同名多实体→ambiguous，不强行映射）。

## 五、装配主链路（写新项目）

**确定性主链路（零 LLM，可复现）**：

```
Schema Diff → Asset Resolver → Reuse Policy → Asset Assembler → Validation Engine → Asset Publisher
(schema_diff) (library)   (decide_strategy) (assemble)     (validate+gate)      (AssetPublisher)
```

**LLM 辅助（仅语义判断，必须经 validator）**：语义映射（resolve_concept，Ossie 字典命中，未命中交语义分类器）、语义分类（semantic_classify，默认确定性）、Claim 抽取/论证（Skill 调 LLM + 结构化输出 + 失败重试）。

**8 个操作类型**（contracts.PATCH_OPERATIONS）：REUSE / PARAMETERIZE / ADD / MODIFY / MAP / DEPRECATE / REBUILD / REJECT。每个 AssetPatch 必须带 base_version（乐观锁）；历史模板版本不可被项目级装配直接覆盖。

**数据契约**：SchemaDiff（added/removed/type_changed/renamed/semantic）、ReuseDecision（strategy/reason/modify_template）、ImpactGraph（16 域 {affected, action}）、AssetPatch（target_asset/operation/payload/base_version）、AssemblyManifest（project_id/based_on/reuse_mode/reused_assets）、Bundle（project_id/version/content_hash/published）、ValidationReport（gate/undefined/replay_conflicts）、ReuseLineage（corpus_node_id/project_node_id/status/note）。

**可插拔开源框架对接**：Apache Ossie（语义对齐标准字典，import/export_ossie_yaml）、Jev TypeSafe（语义分类，预留 MCP 插槽）、Semantica（OWL/SHACL/SKOS 本体管理，预留 semantica_client）。

## 八、验收标准（回归测试即验收，21 个测试文件全部通过）

1. 新增 claims → 识别新增字段 + 兼容性分析
2. 缺非必填字段 → 允许装配并记录缺失
3. 同名异义 → 不直接映射，rebuild
4. Skill 不接受新字段 → 报 Schema 不兼容，不静默丢弃
5. 新增 Claim 无证据 → 保留 unverified，不升级为事实
6. 新增字段影响多节点 → 完整影响清单（16 域）
7. DAG 失败 → 不发布，下游跳过
8. 版本冲突 → base_version 过期检测
9. 无权限 → 拒绝读取/复用
10. 同输入同配置 → 等价结果（content_hash 确定性）
11. 草稿不可见 → list_packages 默认只 published，发布后可见
12. 依赖图精确传播 → ontology 变更覆盖 16 域、variable 不误伤 report_structure
13. 三关口拦截 → QG1/QG2/QG3 检查项与失败关口
14. 知识≠能力 → 仅描述判 induced（候选），有代码判 registered（能力）
15. 跨文档实体 → 同名多实体判 ambiguous，不强行映射
