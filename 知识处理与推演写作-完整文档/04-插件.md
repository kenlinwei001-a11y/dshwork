# 插件（Plugins）

> 知识处理 + 推演写作体系在 WorkDSH 中涉及的插件、注册机制与关键配置。

## 一、插件清单与职责

| 插件 | 包名 | 职责 | 相关状态 |
|---|---|---|---|
| MCP 客户端（核心桥） | `@deepseek-ai/dsh-mcp-client` | 实际 spawn stdio/HTTP MCP 服务进程，注册 `mcp__<serverName>__<tool>` 工具到 Host | 通过连接器动态配置条目运行 |
| MCP 连接器（管理面） | `dsh-mcp-connector` | `mcp_connector_*` 工具族（catalog/configure/status/tools_list/health_check/policy 等）、连接器目录、侧边栏入口 | `showSidebarEntry: true`（曾因 Harness 0.1.7 移除 settingsScope 被本地补丁隐藏，已恢复） |
| 连接器管理（装配面） | `workdsh-plugin-connectors` | `workdsh_connectors` 存储域（connector 定义）、`/api/workdsh-connectors` 管理端点、对话输入框「连接器」选择器、项目「添加 MCP」数据源 | kp-* 5 组连接定义存于此域 |
| 专家管理 | `workdsh-plugin-experts` | 专家草稿/发布/启用（workdsh_expert_* 工具、`?workdsh-view=experts` 面板） | 两个专家发布于此 |
| 技能管理 | `workdsh-plugin-skills` | 技能草稿/校验/发布（workdsh_save_skill_draft 等工具） | 22 个技能发布于此 |
| 项目 | `workdsh-plugin-projects` | 项目工作台、任务能力选择（skill/expert/connector） | 「添加 MCP」读 `/api/workdsh-connectors` |

## 二、MCP 注册架构（重要经验）

### 两套连接器系统，两条 spawn 通道

1. **dsh-mcp-connector（`mcp_connector_*` 工具）**：管理面。`mcp_connector_configure` 会经 `ctx.loader.create` 动态创建 `@deepseek-ai/dsh-mcp-client` 条目 → 实际 spawn。
2. **workdsh-plugin-connectors（`workdsh_connectors` 存储域）**：装配面。连接定义存于 `storages/workdsh_connectors/definitions/*.json`；启动时经 `ctx.plugin(McpClient, …)` 逐条 spawn。项目「添加 MCP」与对话「连接器」按钮读它。
3. **cordis.patch.yml 静态条目**：也可直接声明 `@deepseek-ai/dsh-mcp-client` 条目。

### 曾经踩过的坑（现已修复并记录在案）

- **重复 spawn 冲突**：同一 `serverName` 同时在 cordis 静态条目 + dsh-mcp-connector + workdsh_connectors 三处注册，后加载条目会因同名失败，表现为列表里看不到/offline。**正确做法：一个 serverName 只留一条 spawn 通道**（kp-* 现统一走 workdsh_connectors）。
- **帧格式**：MCP SDK v2 stdio 用 **NDJSON（一行一个 JSON）**，不是 LSP Content-Length 帧。服务器必须回显客户端请求的 protocolVersion（如 2025-11-25）。
- **host-tools-pending**：连接器管理面状态与 Host 工具注册是两层；以 health_check（Host 已注册 N 工具）为准。

### kp-* 5 组连接定义（当前生效）

存储于 `~/.test-runtime/preview/storages/workdsh_connectors/definitions/`：

```
kp-processing.json  kp-assembly.json  kp-library.json  kp-semantic.json  kp-reserved.json
```

每个定义：`transport=stdio`、`command=<工程>/.venv/bin/python`、`args=mcp/servers/kp_<组>_server.py`、`enabled=true`。修改后需重启 DSH Host 生效。

## 三、专家与技能插件数据

- 专家草稿/发布：`~/.agents/.workdsh-state/experts/`
- 技能草稿：`~/.agents/.workdsh-state/skills/drafts/`；正式技能根：`~/.agents/skills/`
- 发布动作只能由用户在受信 UI 确认（workdsh_expert_request_publish → 专家面板点「发布」）。

## 四、客户端入口

- 专家面板：`?workdsh-view=experts`（含 `expert-draft=<id>` 草稿直达）
- MCP 连接器侧边栏入口：`dsh-mcp-connector` 的 `showSidebarEntry=true`（侧边栏 footer）
- 对话输入框「连接器」选择器：`workdsh-plugin-connectors` 注入 `conversation.input.left` slot
- 项目「添加 MCP」：项目工作台 → 能力选择 → connector 类 → 读 `/api/workdsh-connectors` list
