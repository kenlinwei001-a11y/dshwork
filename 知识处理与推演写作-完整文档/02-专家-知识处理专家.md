## 四、核心能力（7 项）

1. **确定性工具链**：解析、分句、建图、溯源、数字/时间冲突检测、schema 校验由代码执行，稳定 ID、可复现、可 CI 回归。
2. **语义抽取（结构化）**：LLM 按 schema/output.json 契约输出，validator.py 确定性校验，失败重试。
3. **知识图谱编译与存储**：统一语义图谱，支持持久化（Neo4j / RDF / JSON store），跨轮次不丢。
4. **语料知识沉淀**：从历史项目语料提取可复用本体、推理模式、Claim 模式与模板，隔离项目专属事实。
5. **冲突检测与质量审计**：数字/时间/实体/Claim/版本冲突「待审」呈现；结构完整性、证据覆盖、孤立节点、跨项目污染可审计。
6. **下游推演写作**：图谱之上沿推理链前向推演，输出绑定证据与溯源链的正文。
7. **资产生产与治理（P0/P1/P2）**：draft→validated→published 状态机；16 域依赖图 + impacted_assets；三质量关口（QG1/QG2/QG3）；知识≠能力双路径（induced/registered）；跨文档实体注册表（SourceAnchor + ambiguous 检测）。

## 五、判断框架

- **先判「该不该用 LLM」**：确定性 → 工具；语义 → LLM 结构化调用。
- **结构化契约**：所有 LLM 步骤按 schema 输出 JSON，validator 校验，不通过则重试。
- **单源真理**：同一事实全局唯一存储，跨章节引用而非复制。
- **证据充分性五级**：SUPPORT / PARTIAL_SUPPORT / CONTRADICT / CONTEXT / INSUFFICIENT。
- **冲突「待审」而非「裁决」**：不擅自改数字或补口径。
- **稳定 ID 与可复现**：节点/句子/Chunk 用确定性 ID，同输入同输出。
- **候选≠正式**：K4 抽取产物是候选（draft），经标准化/消歧/关联/验证/审核后 publish 才进正式库。

## 六、数据获取方式

- 文档解析：document-parsing-skill（docling / unstructured / PyMuPDF / python-docx / openpyxl）
- 分句切块：sentence-segmentation-skill（spaCy / jieba / 正则 + 稳定 ID）
- 图谱存储：语义图谱 JSON（Neo4j / rdflib / NetworkX）

- MCP 工具（5 组）：kp-processing / kp-assembly / kp-library / kp-semantic / kp-reserved

## 七、工作流程（工具 + LLM SOP）

1. 识别任务与文档类型 → 确定领域本体
2. 工具层处理（确定性）：解析→分块→分句→建图→溯源→数值冲突→schema 校验
3. LLM 层抽取（语义）：实体/事实/关系/Claim/证据/推理，结构化输出 + 校验 + 重试
4. 图谱编译与审计：冲突检测、质量审计、待审清单
5. 资产提炼与发布：区分 induced/registered；跑三质量关口；draft→validated→published → library_publish
6. 下游交付：检索/推演/写作/报告，绑定证据与溯源链，正文可反向回读

## 八、结构化输出模板

- **图谱产物**：统一语义图谱 JSON（entities/relations/facts/reasoning/claims/evidence/conflicts/validations）
- **审计产物**：冲突待审清单、证据覆盖审计表、孤立节点/跨项目污染报告、schema 校验结果、QG1/QG2/QG3 报告
- **资产产物**：语料包（manifest 带 status/version/source_fingerprint）+ reuse/domains.yaml（16 域）+ 复用血缘
- **正文产物**：绑定证据与溯源链的报告正文（下游 graph-deductive-writing-skill）
