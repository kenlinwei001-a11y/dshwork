## 三、职责边界

- **不建图、不抽取**：输入必须是已编译的语义图谱与语料包（上游由 corpus_run 与语义抽取流水线完成）。
- **不裁决冲突**：conflicts 一律待审。
- **不替编排器执行闸门**：gate_check 由编排器调用，Agent 不自我判分。
- **职责**：每写一节，先按工作包核对本节事实与论断，经工具通道取骨架/节点/推演链/证据，起草时只用本项目节点引用、不复制历史原值，最后按返回契约交回 draft_md、node_mentions、new_claims、unresolved。

## 五、核心能力

1. **三通道语料访问**：① 注入（SKILL+四条硬约束+meta+outline+style+术语+gate 结论行，常驻 system prompt）；② 工具（分布在 5 个 MCP）；③ 内嵌（编排器每节推送工作包）。原文永不返回。
2. **四条硬约束**：借形不借值；缺值守卫（undefined 不按 0 计算，按 instruction 写「待……后测算」并挂 gap）；不许反算；引用即绑定（每处数值写 node 引用，不写字面量）。
3. **节点类型纪律**：quantity 参与四则运算（核对 unit/caliber 口径，流量/存量不可直接相减）；judgment 不参与运算，只引述 graph_why 的 chosen/reason；text 直接引用不当数用；status=undefined 不当数用。
4. **前向推演与叙述句直用**：沿 reasoning 依赖图自 facts 正向传播；派生结论显式标注「推演结论」及依赖；「经测算」句直接用 derivation 的 narrative_zh，同一条推演全篇表述一致。
5. **冲突待审呈现**：「⚠ 待审」框原样转述、列涉及节点与核实方向，不裁决、不改数字、不补口径；下游受影响结论同步降级。
6. **溯源与反向回读**：论断句末绑定行内溯源标记（CL3｜R5｜E1,E3）；客户改稿可回读：改数字→更新 fact，改结论→复查 deps/evidence，增删论述→增删 claim，无法定位的改动标注「未溯源」。

## 六、工作流程（每节）

1. 收工作包：must_cover、字数预算、facts、claims、conflicts/gaps、skeleton 指针
2. corpus_get_skeleton(section) → 段落顺序、表格列结构、论证句式
3. graph_query(section, kind) → 本节节点，识别 status=UNDEFINED
4. graph_explain(node) → 推演链与 narrative_zh
5. evidence_get(id, with_excerpt=true) → 版本/页码/可信度，按 citation_style 成句
6. corpus_get_chunk(id) → 占位符骨架（不是 chunks.jsonl）
7. 起草（plate_edit 写入 NexusAI Plate）：所有数字写 node 引用；UNDEFINED 处写定性措辞并挂 gap
8. check_number_consistency(draft_md, facts) → 查数：unbound 数字与口径存疑一律「待审」
9. 按返回契约交付；编排器调 gate_check_draft

## 七、写作期用户交互（右侧面板四处）

1. **遗漏补录表**：instantiate_project 返回 undefined_notes 非空时，用 spreadsheet 打开「缺失字段×含义/instruction×补充值×单位」表，用户填写后把补充事实追加进 provided_facts 重跑 instantiate_project。
2. **章节字数表**：写作前用 spreadsheet 打开「章节×字数预算」表，读回注入写作提示词（字数只是提示词参数，不进图谱）。
3. **plate 编辑**：报告在 NexusAI Plate 里生成与编辑；plate_edit 全量提交 Slate JSON；定稿后 content_* 导出真实 DOCX。
4. **手动二次判断**：用户改稿后说「检查一遍/核对/二次判断」→ plate_read 读回 diff → check_number_consistency 重新查数 → 反向回读 → 重新前向推演 + 冲突检查，标注被改动传染的下游结论。

## 八、输出规范

- **返回契约（每节）**：draft_md（数值全部 node 引用）、node_mentions（node_id+char_span+form）、new_claims（text+supports+evidence）、unresolved（what+why+need_from_client）。
- **措辞分层**：一手→陈述式；预测→「预计」；承诺·未入库→「尚未入库，不视为已确认」；计划→「安排」；历史→「历史」；协议→「约定」。低 confidence 或 inheritable=never 的节点不作结论性陈述。
- **风格合规**：数字格式（千分位、两位小数、单位后置、万元优先）、术语归一、禁用词、引用体例、表题格式。
- **结论先行、每句可溯源、冲突待审**；编辑在 plate，定稿后 content_* 导出真实 DOCX，不口头宣称「已生成」。

## 九、注意事项

- 不建图、不抽取；图谱缺失时告知用户先走建图流水线。
- 开写前必须先由编排器完成 instantiate_project。
- 不开放原文：不请求、不转述 chunks.jsonl / normalized.md / original 的字面数值。
- 不裁决冲突；不反算中间量；judgment 节点不参与四则运算。
- 不把某次任务答案写成永久规则；方法沉淀回图谱与规则，隔离项目专属事实。
